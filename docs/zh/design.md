# 工作原理

## 两类进程

folio 是一个 Electron 应用，Electron 将它分为两部分：

- **主进程**掌管窗口、菜单、磁盘和网络规则。只有它读写文件。
- **文档窗口**负责绘制文档。它在上下文隔离和 Chromium 沙箱中运行，没有 Node.js，
  并受内容安全策略约束，只允许 folio 自己的脚本。它能向主进程请求的内容都经过一座
  小桥（preload 脚本）——打开、保存、读取项目中的文件——除此之外别无其他。

## 文档能做什么


Markdown 文件可能来自任何地方，因此窗口不信任它：

- 它只能看到打开它的文件夹中的文件（由 folio 自己的协议提供），看不到该文件夹之外的任何内容；
- 只有在你为该文件或文件夹授权后，它才能访问网络——API 参考中的“试一试”、按 URL 加载的图片或视频；
- 它不能把窗口导航到其他页面，也不能打开新窗口；链接会交给系统浏览器打开。

## 窗口

中间留给页面；控件位于四周。

- **左侧——工作区。** “共享”与各个项目，每个都是其文档的树。顶部：打开文件、新建快速笔记、折叠。每个分区有自己的菜单：
  “共享”——其文件夹；“项目”——**+** 添加文件夹或克隆仓库，**⋯** 显示隐藏的项目。仓库的分支以名称旁的标签显示。
  **折叠后**（`Cmd/Ctrl+B`）侧边栏是一条窄栏——“共享”和各项目以首字母显示——点击会在页面上方滑出其文件树，直到打开文档。
- **顶部——标签页**，仅此而已。
- **编辑器的工具栏悬浮在页面上方**，无论文本向下多远都触手可及；页面本身没有边框。在 **Markdown** 模式下文本占满整个工作区；**与页面并排**时两半以一条线相接，各自滚动。
- **右侧——工具栏。** 一个按钮显示文档当前的显示方式，单击按顺序切换模式——**阅读**、**可视化编辑**、**Markdown**、
  **Markdown 与页面并排**（图表提供阅读和编辑，draw.io 仅阅读）；右键列出所有模式以直接选择。然后是历史、打印和 PDF；底部是设置（主题：跟随系统、浅色、深色）。

## 打开文档

可以通过 **文件 → 打开**、把文件拖到窗口上、从命令行（`folio notes.md`）打开 Markdown
文件；如果 folio 已在运行，再次带文件启动时会由正在运行的 folio 打开它。指向同一文件夹中
另一个文档的链接会在标签页中打开该文档。重启后，打开过的文档和当前文档都会恢复。

### 图表与 API 文件

不只是 Markdown：图表或 API 描述会在自己的标签页中打开，由对应的 embed 元素绘制；文档中指向这类文件的链接同样会打开它们。

| 文件 | 绘制方式 | 编辑方式 |
|---|---|---|
| `.bpmn`、`.dmn` | `<dsk-bpmn>`、`<dsk-dmn>` | 各自的编辑器：组件面板、上下文菜单、属性、撤销 |
| `.drawio`、`.dio`、`.drawio.svg` | `<dsk-drawio>`，带页面标签 | —（仅查看） |
| OpenAPI / Swagger（`.yaml`、`.yml`、`.json`） | `<dsk-openapi>`，参考文档 | 其可视化编辑器，含源码与预览 |
| AsyncAPI（`.yaml`、`.yml`、`.json`） | `<dsk-asyncapi>` | 源码与实时预览并排 |
| `.mmd`、`.puml`、`.dot`、`.gv`、`.d2`、`.dbml`、`.dsl`、`.wardley` | `<dsk-diagram>`，按扩展名确定语法 | 源码与实时预览并排 |
| 代码、数据、日志、配置——任何已知语言的文本文件（17 种编程语言、JSON、XML、日志、TOML、INI、`.env`、CSV、diff、Dockerfile、Makefile……） | 带行号、按其语言着色（`@dskripchenko/syntax`；语言按文件名、扩展名或 `#!` 行判断）；数据文件（JSON、YAML、XML、TOML、CSV、INI、`.env`）会被校验——错误标在对应行号处，顶部计数可逐个跳转；代码块可通过行号旁的箭头折叠；大文件（超过 2 MB 或 20 000 行，最大 200 MB）只绘制可见行，超过 5 MB 时只读；日志可按级别筛选（堆栈跟踪随其条目），停在末尾阅读时会跟随新写入的内容 | 源码 |
| 其他文本 | 作为文本 | 源码 |

YAML 和 JSON 通过顶层的 `openapi`、`swagger` 或 `asyncapi` 键识别；文件树列出 YAML 文件以及名称类似 API 描述的
JSON 文件（`openapi.json`），而不是每个 `package.json`。没有网络服务器地址的 API 不提供“试用”，其请求示例使用
`http://localhost`。保存、在重启后仍保留的未保存修改、历史记录及其比较，对这些文件与 Markdown 一样适用。

## 共享与项目

工作区分为两部分：**共享**——存放通用文档的一个文件夹（默认是 `folio-data/library`，
也可以选择自己的文件夹）；**项目**——添加到 folio 的任意磁盘文件夹。列表保存在
`folio-data/workspace.json` 中；文件夹本身保持原位。项目或共享中的文档可以读取整个
文件夹的文件；单独打开的文件只能读取它所在的文件夹。

侧边栏显示“共享”和各项目：先是固定的项目，然后按分组，最后是其余项目；项目菜单（右键）
可以固定、重命名、放入分组、隐藏或从 folio 中移除（磁盘上的文件夹保留）。树中列出文件夹和
folio 能打开的文件，文件夹在前，并跟随磁盘变化：在别处新增、修改或删除的文件会立即显示，
打开的文档会重新绘制。`Cmd/Ctrl+B` 可隐藏侧边栏。

## 使用 git 的历史

按文件夹分别设置——“共享”和每个项目——且仅在你需要时启用。作为 git 仓库（或位于其中）的
文件夹会直接显示历史；其他文件夹可以在 **历史** 面板（`Cmd/Ctrl+Shift+H`）中点击
**保留历史** 来开始：在 `main` 分支上创建仓库，并对现有内容做第一次提交。

- **保存时提交**——由 folio 开始的历史默认开启，已有的仓库默认关闭（folio 不会擅自向项目
  提交）。保存的文件会在最后一次保存 3 分钟后提交，因此连续多次保存只产生一次提交；退出
  folio 时会立即提交待提交的内容。只提交被保存的文件，提交信息为 *Update <路径>*；
  使用 **提交** 并填写自己的说明可立即提交。
- 打开文件的 **版本**，最新的在前。版本以只读方式按原样打开；**更改** 逐行显示它与当前的
  差异，**并排** 显示两个绘制好的文档（包括图表）。**恢复此版本** 会把它的文本作为未保存的
  修改放入编辑器——是否保存由你决定。
- **在树中**：修改过的文件会被标记，内部有修改的文件夹带一个圆点，项目显示其分支。
- 作者取自仓库配置中的 `user.name` / `user.email`，其次是 `~/.gitconfig`，否则为系统用户。

git 内置于 folio（isomorphic-git，纯 JavaScript），因此在未安装 git 的机器上也能使用。

### 分支与同步

- **分支**：点击面板中的分支名会打开列表——切换到其他分支，或从当前位置新建分支。
  如果文件中有会被切换覆盖的修改，切换会被拒绝（正在等待暂停的提交会先完成）。
- **远程仓库**：没有远程的文件夹可在面板中填写地址；在 folio 中克隆的仓库
  （**文件 → 克隆仓库…**，或“项目”旁的 ⤓）自带远程，并成为开启了“保存时提交”的项目。
- **同步**会抓取远程、接收远程的提交（快进；若双方都有新提交则生成合并提交），
  再发送你的提交；按钮上显示双向的数量（↑ ↓）。同步前所有修改都需已提交。
- **冲突**会像 git 那样留在文本中：两个版本位于 `<<<<<<<` 与 `>>>>>>>` 行之间，
  面板列出相关文件。编辑它们（在 folio 或任何地方）、保存，然后点击**完成合并**——
  只要还有冲突标记就会被拒绝；**取消合并**会回到你的版本。合并状态按 git 的方式保存
  （`MERGE_HEAD`），系统 git 也能看到；在完成之前，保存不会生成提交。
- **网络**：若已安装系统 git，就通过它——其凭据助手和 SSH 密钥的工作方式与终端中一样
  （它不会在无人可见的终端里询问密码）。没有系统 git 时，folio 自己使用 HTTPS：
  远程要求登录时，面板接收用户名和令牌，由系统加密（Keychain、DPAPI、Secret Service）
  保存在 `folio-data/logins.json` 中——若系统没有加密能力，则只在本次会话中保留。
  同步是你主动执行的操作，不需要文档那样的网络许可。

### 提交图

列表旁有一张类似 Fork 的图：每条开发线一条轨道，合并画成连接轨道的圆环，分支在其基线旁并行并在之后弯回。
**此文件**显示该文件的各个版本，线条穿过未改动该文件的提交（与 `git log -- file` 简化历史的方式相同）；
**所有提交**显示整个仓库——其分支、远程仓库在最近一次抓取时的分支以及标签，名称标在对应提交上，当前检出的提交会被标记。
选择某个提交会打开该文件当时的样子。图由 `@dskripchenko/diagrams`（`renderCommitGraph`）绘制。

## 未保存的内容与快速笔记

与 Sublime Text 一样：无标题标签页就是快速笔记，未保存的修改不会写入文件。两者都会在你
输入时写入 `folio-data/session/`，因此能经受关闭 folio、崩溃和重启电脑，并原样恢复。有未保存修改的标签页带有一个圆点。关闭这样的标签页时会询问是否保存；关闭
folio 则什么都不问——所有内容都已在磁盘上。如果在你编辑时文件在磁盘上发生了变化，folio
会提示并保留两者：从磁盘取回文件，或者保留你的版本并覆盖保存。快速笔记通过 **保存**
存入“共享”（或任意位置），以其第一行命名。

## 打印

**文件 → 打印**（`Cmd/Ctrl+P`）将当前文档作为文档打印：以阅读而非编辑模式；folio 的侧边栏、标签页、按钮和历史面板不会出现在纸上，
并且无论屏幕是何种主题，纸面始终为浅色。每个部件都以 embed 提供的打印形式输出（`DskEmbed.print.prepare`）：完整的 BPMN 或 DMN 图
（DMN 文件附带其决策表）、draw.io 的所有页面、完整的流程或白板、作为静态文档的 API 参考、以封面和章节呈现的视频、不含控件的看板和日历。
随后会打开系统打印对话框；PDF 通过“导出为 PDF”保存（见下文）。

### PDF

**文件 → 导出为 PDF**（`Cmd/Ctrl+Shift+P`）保存当前文档——按显示的样子，包括未保存的修改；**将文件夹导出为 PDF**
（项目菜单或文件树中文件夹的菜单）把整个文件夹保存为一个 PDF。对话框只询问一次并记住设置：

- 纸张大小（A4、A3、A5、Letter、Legal、Tabloid），纵向或横向，页边距（无、窄、常规、宽）；
- 每页顶部的标题，底部的页码（`3 / 12`）；
- 正文之前带链接的目录；根据标题生成的书签（PDF 大纲，生成带标签的 PDF）；
- 图表的颜色和背景。

文件夹按书的顺序打印：每个文件夹中先是 `index.md` 或 `README.md`，然后按名称排列的文档，再是子文件夹；
每个文档从新的一页开始，图表和 API 文件以文件名作为标题。从一个文档指向另一个文档的链接会变为 PDF 内部的链接。
页面在文档会话的隐藏窗口中排版——网络许可在那里同样有效——每个部件都以其打印形式呈现，然后由 Chromium 打印为 PDF。

## 编辑

`Cmd/Ctrl+E`（或工具栏上的 **编辑**）可在编辑器与阅读之间切换。编辑器有三种模式：
可视化（像文字处理器一样编辑——工具栏、`/` 菜单，所有块都是实时的）、Markdown 本身，
以及两者并排。文件始终是 Markdown：可视化模式无法容纳的内容（h3 以下的标题、任务列表、
提示框、HTML）按原样保留，图片也保留其相对路径。

| 按键 | |
|---|---|
| `Cmd/Ctrl+N` | 快速笔记 |
| `Cmd/Ctrl+O` | 打开文件 |
| `Cmd/Ctrl+S`、`Cmd/Ctrl+Shift+S` | 保存、另存为 |
| `Cmd/Ctrl+E` | 编辑 / 阅读 |
| `Cmd/Ctrl+T` | 按名称转到文件 |
| `Cmd/Ctrl+F` | 在文档中查找 |
| `Cmd/Ctrl+G`、`Cmd/Ctrl+Shift+G` | 下一个匹配、上一个 |
| `Cmd/Ctrl+W` | 关闭标签页 |
| `Cmd/Ctrl+B` | 侧边栏 |

## 查找

`Cmd/Ctrl+T`（**文件 → 转到文件**）打开一个面板，列出“共享”和可见项目中 folio 能打开的所有文件，随输入的名称排序：
字符按顺序出现即可，不必连续——`rn` 能找到 `release-notes.md`；单词首字母权重最高，名称中的匹配高于文件夹中的匹配。
方向键选择，Enter 打开，Escape 退出。每个文件夹的列表只遍历一次，在其中有文件新增或删除前一直保留；
依赖和构建输出文件夹（`vendor`、`dist`、`build`、`target`、`coverage`……）不在其中，尽管文件树会显示它们。

`Cmd/Ctrl+F`（**编辑 → 查找**）在页面上方打开查找栏：所有匹配都会标出，当前匹配会滚动到可见处；Enter 和 Shift+Enter
在匹配间前后跳转，计数显示当前位置。**Aa** 区分大小写，**ab** 匹配整个单词（任何文字），**.\*** 使用正则表达式。
阅读模式和可视化编辑器搜索绘制出的页面——匹配不会跨段落，页面本身也不会被改动；Markdown 源码和以文本方式编辑的文件搜索的是输入框，
按 Escape 后当前匹配会在其中保持选中；大文件会整体搜索，而不只是可见的行。查找栏下的页面发生变化（编辑、磁盘上的文件被修改）时会重新搜索。

## 数据存放在哪里

Electron 默认把数据存放在用户配置目录中。folio 把所有数据——设置、缓存、会话数据、
日志——都移到程序旁边的 `folio-data/` 中：

| 运行方式 | `folio-data/` 位于 |
|---|---|
| Windows | `folio.exe` 旁边 |
| macOS | `folio.app` 旁边 |
| Linux | `.AppImage` 文件旁边 |
| 设置了 `FOLIO_DATA` | 该目录 |
| 从源码运行 | 工作目录中的 `.folio-data/` |

因此，删除程序所在的文件夹就会删除它写入过的一切。反过来说：该文件夹必须可写——
不要把 folio 解压到只有管理员才能写入的位置。

## 单一窗口

再次启动会把正在运行的 folio 切到前台，而不是启动第二个副本；文档以该窗口的标签页形式打开。
