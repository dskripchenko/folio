# 工作原理

## 两类进程

folio 是一个 Electron 应用，Electron 将它分为两部分：

- **主进程**掌管窗口、菜单、磁盘和网络规则。只有它读写文件。
- **文档窗口**负责绘制文档。它在上下文隔离和 Chromium 沙箱中运行，没有 Node.js，
  并受内容安全策略约束，只允许 folio 自己的脚本。它能向主进程请求的内容都经过一座
  小桥（preload 脚本）——打开、保存、读取项目中的文件——除此之外别无其他。

## 文档能做什么


Markdown 文件可能来自任何地方，因此窗口不信任它：

- 它只能看到打开它的文件夹中的文件（由 folio 自己的协议提供），看不到该文件夹之外的任何内容；
- 只有在你为该文件或文件夹授权后，它才能访问网络——API 参考中的“试一试”、按 URL 加载的图片或视频；
- 它不能把窗口导航到其他页面，也不能打开新窗口；链接会交给系统浏览器打开。

## 窗口

中间留给页面；控件位于四周。

- **左侧——工作区。** “共享”与各个项目，每个都是其文档的树。顶部：打开文件、新建快速笔记、折叠。每个分区有自己的菜单：
  “共享”——其文件夹；“项目”——**+** 添加文件夹或克隆仓库，**⋯** 显示隐藏的项目。仓库的分支以名称旁的标签显示。
  **折叠后**（`Cmd/Ctrl+B`）侧边栏是一条窄栏——“共享”和各项目以首字母显示——点击会在页面上方滑出其文件树，直到打开文档。
- **顶部——标签页**，仅此而已。
- **编辑器的工具栏悬浮在页面上方**，无论文本向下多远都触手可及；页面本身没有边框。在 **Markdown** 模式下文本占满整个工作区；**与页面并排**时两半以一条线相接，各自滚动。
- **右侧——工具栏。** 一个按钮显示文档当前的显示方式，单击按顺序切换模式——**阅读**、**可视化编辑**、**Markdown**、
  **Markdown 与页面并排**（图表提供阅读和编辑，draw.io 仅阅读）；右键列出所有模式以直接选择。然后是历史、打印和 PDF；底部是设置（主题：跟随系统、浅色、深色）。

## 打开文档

可以通过 **文件 → 打开**、把文件拖到窗口上、从命令行（`folio notes.md`）打开 Markdown
文件；如果 folio 已在运行，再次带文件启动时会由正在运行的 folio 打开它。指向同一文件夹中
另一个文档的链接会在标签页中打开该文档。重启后，打开过的文档和当前文档都会恢复。

### 图表与 API 文件

不只是 Markdown：图表或 API 描述会在自己的标签页中打开，由对应的 embed 元素绘制；文档中指向这类文件的链接同样会打开它们。

| 文件 | 绘制方式 | 编辑方式 |
|---|---|---|
| `.bpmn`、`.dmn` | `<dsk-bpmn>`、`<dsk-dmn>` | 各自的编辑器：组件面板、上下文菜单、属性、撤销 |
| `.drawio`、`.dio`、`.drawio.svg` | `<dsk-drawio>`，带页面标签 | —（仅查看） |
| OpenAPI / Swagger（`.yaml`、`.yml`、`.json`） | `<dsk-openapi>`，参考文档 | 其可视化编辑器，含源码与预览 |
| AsyncAPI（`.yaml`、`.yml`、`.json`） | `<dsk-asyncapi>` | 源码与实时预览并排 |
| `.mmd`、`.puml`、`.dot`、`.gv`、`.d2`、`.dbml`、`.dsl`、`.wardley` | `<dsk-diagram>`，按扩展名确定语法 | 源码与实时预览并排 |
| 代码、数据、日志、配置——任何已知语言的文本文件（17 种编程语言、JSON、XML、日志、TOML、INI、`.env`、CSV、diff、Dockerfile、Makefile……） | 带行号、按其语言着色（`@dskripchenko/syntax`；语言按文件名、扩展名或 `#!` 行判断）；数据文件（JSON、YAML、XML、TOML、CSV、INI、`.env`）会被校验——错误标在对应行号处，顶部计数可逐个跳转；代码块可通过行号旁的箭头折叠；大文件（超过 2 MB 或 20 000 行，最大 200 MB）只绘制可见行，超过 64 MB 时只读；日志可按级别筛选（堆栈跟踪随其条目），停在末尾阅读时会跟随新写入的内容 | 代码编辑器 |
| 其他文本 | 作为文本 | 代码编辑器 |

**代码编辑器**（`@dskripchenko/code-editor`）编辑所有文本文件，以及与预览并排的图表记法和 AsyncAPI：
输入时高亮，可通过行号旁的箭头折叠，数据文件边写边校验。按键与 VS Code 相同——括号和引号自动闭合，
`Cmd/Ctrl+/` 注释行，`Alt+↑/↓` 移动行，`Cmd/Ctrl+D` 把下一个出现位置加入光标，`Ctrl+Space` 用文件中的单词补全。
缩进取自项目的 `.editorconfig`，否则取自文件本身；状态栏显示行和列、缩进、换行符（LF 或 CRLF，保持原样）和语言。
64 MB 以内的文件可编辑；更大的文件只读。

YAML 和 JSON 通过顶层的 `openapi`、`swagger` 或 `asyncapi` 键识别；文件树列出 YAML 文件以及名称类似 API 描述的
JSON 文件（`openapi.json`），而不是每个 `package.json`。没有网络服务器地址的 API 不提供“试用”，其请求示例使用
`http://localhost`。保存、在重启后仍保留的未保存修改、历史记录及其比较，对这些文件与 Markdown 一样适用。

## 共享与项目

工作区分为两部分：**共享**——存放通用文档的一个文件夹（默认是 `folio-data/library`，
也可以选择自己的文件夹）；**项目**——添加到 folio 的任意磁盘文件夹。列表保存在
`folio-data/workspace.json` 中；文件夹本身保持原位。项目或共享中的文档可以读取整个
文件夹的文件；单独打开的文件只能读取它所在的文件夹。

侧边栏显示“共享”和各项目：先是固定的项目，然后按分组，最后是其余项目；项目菜单（右键）
可以固定、重命名、放入分组、隐藏或从 folio 中移除（磁盘上的文件夹保留）。树中列出文件夹和
folio 能打开的文件，文件夹在前，并跟随磁盘变化：在别处新增、修改或删除的文件会立即显示，
打开的文档会重新绘制。`Cmd/Ctrl+B` 可隐藏侧边栏。

在代码编辑器中，文件的**符号**——函数、类、方法、类型、常量；配置的键和节——会随输入读取：**大纲**（右侧栏）列出它们，
标记光标所在的符号，点击即跳转；文本上方的面包屑显示文件的项目和文件夹，以及包含光标的符号；`Cmd/Ctrl+Shift+O` 按名称跳转到
文件中的符号，`Cmd/Ctrl+Alt+O` 跳转到任一可见项目的符号（在编辑器中打开其文件并定位）。自动补全除文件自身的单词外，还提供各项目中的名称。

**任务**（`Cmd/Ctrl+Shift+B`，或命令中的*运行任务*）属于项目自身：`package.json` 的脚本（用锁文件指明的包管理器运行）和
`composer.json` 的脚本、`Makefile` 的目标、`justfile` 的配方，以及 `.folio/settings.json` 中的任务；最近运行的排在前面。
任务在以其命名的独立控制台标签页中运行，随任务结束。其输出会被解析出**问题**——`路径:行:列: 消息`（gcc、clang、go、ruff、
mypy、pytest、eslint 的 unix 格式）、tsc、eslint 的 stylish 块、rustc、psalm——显示在**问题**面板中（右侧栏，任务发现问题时自动打开），
每条都能跳转到对应位置，并在代码编辑器中加下划线。

代码项目可以在**保存时格式化**，使用项目自己的格式化工具——prettier（项目自带的）、pint、gofmt、ruff、rustfmt、black，
或从 stdin 读取文本的自定义命令——前提是 `.folio/settings.json` 中这样设置；只修改格式化工具改动的部分，可一步撤销。

项目根目录的 `.folio/settings.json` 保存项目自己的设置，需手动编写（如项目成员愿意，可随项目提交）：

```json
{
  "kind": "code",
  "indentUnit": "  ",
  "tabSize": 2,
  "formatOnSave": true,
  "formatter": "prettier",
  "tasks": [{ "name": "serve", "command": "php artisan serve" }],
  "lsp": { "php": ["phpactor", "language-server"], "python": false }
}
```

类型优先于自动判断的类型，缩进优先于 `.editorconfig`。自定义按键写在 `folio-data/keybindings.json` 中，没有单独的设置界面：
`[{ "key": "Mod-Shift-d", "command": "copyLineDown" }, { "key": "Mod-Alt-p", "command": "folio.problems" }]`
——代码编辑器的命令用其名称，folio 的命令用 `folio.` 加命令 id；在编辑器中，编辑器自己的按键优先于 folio 的快捷键。

**语言服务器**（LSP）在本机装有时理解编辑器中的代码：`typescript-language-server`、`intelephense` 或 `phpactor`、
`pyright` 或 `pylsp`、`gopls`、`rust-analyzer`、`clangd`——folio 不自带任何服务器。打开某语言的文件即为该项目启动其服务器
（最后一个文件关闭几分钟后停止）；项目自带的服务器（`node_modules/.bin`、`vendor/bin`、`.venv/bin`）只有在信任该项目后才运行，
只询问一次。之后问题在输入时即加下划线并列入**问题**面板；指针停在名称上显示它是什么；`F12` 或 `Cmd/Ctrl`+单击转到定义，
`Shift+F12` 列出引用，`F2` 在整个项目中重命名（已打开的文件在其标签页中修改，每个标签页一次撤销），`Cmd/Ctrl+.` 提供服务器的修复；
补全优先列出服务器的条目，调用的参数在 `(` 之后显示（`Cmd/Ctrl+Shift+Space`），大纲和面包屑来自服务器。状态栏显示服务器名称，
或应安装什么；命令中的*语言服务器输出*显示其日志。`.folio/settings.json` 中的 `"lsp"` 为某语言指定自己的命令，`false` 表示不用服务器；
`"formatter": "lsp"` 在保存时由服务器格式化。

**图片、视频和音频**在自己的标签页中打开：PNG、JPEG、GIF、WebP、AVIF、BMP 和图标适应视图显示（小图保持原尺寸），
用 `Cmd/Ctrl` 加滚轮或捏合手势围绕指针缩放，`+`、`−`、`0`（适应）和 `1`（原始尺寸），双击在两者间切换，大于视图时可拖动，
透明部分显示在棋盘格上；MP4、WebM、MOV 和 MKV 在视频播放器中播放，MP3、WAV、OGG、Opus、M4A、AAC 和 FLAC 在带波形的音频播放器中播放。
状态栏显示尺寸、时长和大小；文件下方的工具栏可用系统程序打开它——Chromium 无法解码的文件也会自动提供此选项。
SVG 会被绘制，并在其图像旁作为文本编辑，图像随输入更新。它们也会出现在笔记的文件树中，但从不作为文本读取：搜索、文件夹 PDF 和历史版本都会跳过它们。

项目分为**笔记**项目和**代码**项目——添加时自动判断（根目录有 `package.json`、`composer.json`、`go.mod`、`Cargo.toml`……，
或是除 README 外没有笔记的 git 仓库，即为代码项目），可在其菜单中更改。代码项目列出所有文件，包括以点开头的文件
（`.github`、`.editorconfig`），非文本文件（图片、视频和音频除外——由 folio 自己显示）用系统程序打开；保存不会自动提交——提交需手动完成。在 git 管理的文件夹中，
`.gitignore`（连同 `.git/info/exclude` 和用户的全局排除文件）排除的内容不会出现在文件树、转到文件和搜索中，
文件树会随 `.gitignore` 的编辑实时更新；没有 git 的文件夹沿用 folio 自己的工具文件夹列表（`node_modules`、`vendor`、`dist`……）。

### 文件和文件夹

文件树也能新建和修改文件：在文件夹或项目的右键菜单（以及“共享”的 **…** 菜单）中选择**新建笔记**和**新建文件夹**——就地输入名称，笔记立即打开并以名称作为标题；
**重命名…**（或 `F2`）在行内编辑名称，扩展名保留；拖到文件夹（或项目）上的文件或文件夹会移动到那里；**复制副本**在旁边生成一份副本；
**移到废纸篓**（或 `Delete`、`Cmd+Backspace`）会先确认，再放入系统废纸篓，可从中恢复。打开的文档会跟随重命名或移动；
被移到废纸篓的文档会关闭，除非它有未保存的更改。含有 `/ \ : * ? " < > |` 的名称或已存在的名称会被就地拒绝并说明原因。

代码文件的名称旁显示其类型：一两个字符，使用其技术栈的颜色——`JS` 黄色、`TS` 蓝色、PHP 为紫色的 `<?`、Blade 为 `B`、JSON 为 `{}` 等；`package.json`、`composer.json`、lock 文件、`Dockerfile` 和 `.env` 按名称识别。**更改**面板和审阅中也使用同样的标记。

### 并排两个文档

标签页菜单中的**在旁边打开**（或 `Cmd/Ctrl+\`，或对应命令）会在右侧的第二个视图中显示该文档；主视图保留另一个标签页。每个视图有各自的文档和滚动位置；在某个视图中点击即把它的文档设为当前文档，面板、查找和历史随之切换。视图之间的分隔条可以拖动，比例会被记住。**放回主视图**（或再次按 `Cmd/Ctrl+\`）关闭侧视图，文档仍在标签页中打开；关闭其标签页也会关闭该视图。打印只打印当前文档。

### 笔记之间的链接

`[[笔记]]` 按名称链接到同一项目（或“共享”）中任意位置的笔记：先找笔记自身所在的文件夹，再找路径最短的。`[[笔记#标题]]` 打开并定位到该标题，`[[笔记|文字]]` 显示其他文字，`![[图片.png]]` 显示图片。指向不存在笔记的链接显示得更淡；点击它会在引用笔记旁新建该笔记并打开。在编辑器中用 `Cmd/Ctrl`+点击打开链接，输入 `[[` 会提示项目中的笔记。在树中重命名或移动笔记或文件夹时，链接随之更新：项目笔记中的 `[[…]]` 链接和相对链接（`[文字](notes/plan.md)`、图片）会被重写，被移动笔记自身的相对链接也一样；带有未保存修改的已打开笔记保持不变。

**链接面板**（右侧栏的链接图标）为当前笔记显示：链接到它的笔记、它自己的链接（不存在的显示得更淡，点击即创建），以及提到它却没有链接的笔记；**链接**按钮把这样的提及变成 `[[笔记]]`（原写法保留为链接文字）。点击某一行会在该处打开笔记。面板跟随当前笔记和输入内容更新。

### 每日笔记与模板

`Cmd/Ctrl+Shift+D`（或命令中的**今日笔记**）打开当天的笔记——每日笔记文件夹中的 `YYYY-MM-DD.md`（默认为“共享”中的 `Daily`）——不存在时会创建，若有 `Daily` 模板则据其生成。**上一篇 / 下一篇每日笔记**跳转到最近的已有笔记。模板是模板文件夹（默认为“共享”中的 `Templates`）中的笔记：**插入模板…**将其插入光标处，**从模板新建笔记…**据其创建快速笔记；`{{title}}`、`{{date}}`、`{{time}}` 和 `{{date:DD.MM.YYYY}}` 会被填入。两个文件夹都在设置菜单中选择。

`![[笔记]]` 把另一篇笔记嵌入当前笔记——按阅读模式绘制，放在带链接的框中；`![[笔记#标题]]` 嵌入该标题的章节。嵌入中的嵌入同样会绘制（最多三层），嵌入自身的笔记保留为链接；在编辑器中嵌入显示为其链接，并按原样保存。

笔记的别名——属性中的 `aliases:`（`aliases: [路线图]`）——在链接中可以当作它的名称使用：没有同名文件时，`[[路线图]]` 会指向它；输入 `[[` 时也会提示别名，并写成 `[[Roadmap|路线图]]`。

### 大纲

大纲面板（右侧栏或命令中）按层级缩进列出当前笔记的标题，并随输入实时更新；点击即跳转到该标题——在源码中会把光标放到对应行——滚动时会标记当前可见的章节。

### 拼写检查与状态栏

输入时检查拼写——在 macOS 和 Windows 上由系统离线完成；在 Linux 上 Chromium 需要下载词典，因此默认关闭，可在设置菜单中开启。输入框的菜单提供更正建议、**添加到词典**以及剪切、复制、粘贴。页面下方的状态栏显示文档的字数、字符数和阅读时长，在 Markdown 源码中还显示光标所在的行和列。

### 关系图

关系图面板（右侧栏或命令中）以点表示当前项目的笔记，以线表示它们之间的链接——**此笔记**：距当前笔记不超过两层链接的笔记；**全部**：整个项目。点的大小表示其链接数量，当前笔记以颜色突出；指针停在点上会高亮它及其相邻笔记，点击即可打开；滚轮缩放，拖动平移画面。

### 书签

常用文件：在标签页菜单、树中文件的菜单或命令中选择**加入书签**。书签列在“共享”上方；点击打开，其菜单可移除书签。在 folio 中重命名或移动文件时书签随之更新；文件在别处消失的书签会保留并淡化显示。

### 看板与日历

`*.kanban.md` 文件以看板打开，`*.calendar.md` 文件以日历打开——两者都用任何编辑器都能读懂的标记写成（列 `## …` 和卡片 `- …`；事件 `2026-11-03 10:00 …`，重复 `every mon …`）。**编辑**后可直接在其上修改：拖动和添加卡片、移动事件，源码在单独的标签页中；文件保存标记，只在修改处变化。命令中的**新建看板**和**新建日历**会在当前笔记旁创建。

### 白板

`*.board` 文件以白板打开（`@dskripchenko/board`）：便签、形状、文字、框架、连线、表情、钢笔和马克笔，画布无限。**编辑** 即可在上面绘制；文件保存带缩进的白板 JSON，差异对比能看出移动了什么。命令面板中的 **新建白板** 会在当前笔记旁创建一个。

### 任务

任务面板（右侧栏或命令中）按到期时间列出当前项目中的 `- [ ]` 任务——**已逾期**、**今天**、**以后**、**无日期**——选择**全部**时也包括已完成的；日期写作 `📅 2026-11-10`、`@2026-11-10` 或 `due:2026-11-10`。可以直接在面板中勾选或取消任务，修改会写入所在笔记（有未保存修改的已打开笔记除外）；点击任务文字会在该处打开笔记。

### 幻灯片

**以幻灯片放映**（`F5` 或命令面板）全屏逐张显示当前笔记：幻灯片是笔记中以 `---` 行分隔的部分（`---` 前须有空行，代码与属性之外，同 Marp 和 reveal.js）。方向键、空格、Page Up/Down、Home 和 End，或点击左右半屏翻页；Escape 结束放映。**将幻灯片导出为 PDF**（命令面板或放映栏）每张幻灯片输出一页 16:9。

### 预览

指针停留在 `[[链接]]` 或指向笔记的链接上时，会在链接旁的窗口中显示该笔记——按阅读模式绘制，并定位到链接所指的标题。窗口可以滚动；在其中点击会打开笔记；移开指针或按 Escape 会关闭它。在编辑器中，预览需要按住 `Cmd/Ctrl`。

### 标签与属性

笔记中的 `#todo`、`#work/urgent` 是标签（至少需要一个字母：`#123` 不是标签，`C#` 也不是）；其属性中的 `tags:` 也是标签。笔记的属性——开头的 YAML front matter，即由 `---` 行包围的 `键: 值`——显示为笔记上方的表格，在编辑器中按原样保存。标签面板（右侧栏的标签图标或对应命令）列出当前项目的标签及其笔记数量，嵌套标签位于其父标签之下；展开的标签显示其笔记，点击即可打开；过滤框按名称查找标签。点击笔记中的标签会在该标签处打开面板（在编辑器中需按住 `Cmd/Ctrl`）。

### 公式与高亮

TeX 公式按其书写方式绘制：行内的 `$E = mc^2$`，以及独占一行的 `$$ … $$`（或 ` ```math ` 代码块）——由 folio 自己的 `@dskripchenko/math` 以 MathML 绘制。价格（`$5 或 $10`）保持为普通文本。在可视编辑器中，公式是一个整体：双击可编辑其 TeX，`/` 菜单中的**公式**可添加新公式，文件按原样保存；Markdown 源码会高亮其中的 TeX。括号和根号在数学字体中伸缩：使用系统自带的字体（macOS、Windows），或 folio 自带的 STIX Two Math（SIL Open Font License）。`==文字==` 会被高亮。

### 图片

粘贴到笔记中的图片（截图、复制的图像）或拖放到编辑器上的图片（可视模式或源码模式）会保存到笔记旁边的 `attachments/` 中，并在光标处插入链接：使用其自身的名称，无名截图则命名为 `Pasted image` 加时间；名称已被占用时追加编号。编辑器工具栏的图片按钮以同样方式从磁盘选择图片。尚未保存的快速笔记会提示先保存——图片需要一个文件夹。

## 使用 git 的历史

按文件夹分别设置——“共享”和每个项目——且仅在你需要时启用。作为 git 仓库（或位于其中）的
文件夹会直接显示历史；其他文件夹可以在 **历史** 面板（`Cmd/Ctrl+Shift+H`）中点击
**保留历史** 来开始：在 `main` 分支上创建仓库，并对现有内容做第一次提交。

- **保存时提交**——由 folio 开始的历史默认开启，已有的仓库默认关闭（folio 不会擅自向项目
  提交）。保存的文件会在最后一次保存 3 分钟后提交，因此连续多次保存只产生一次提交；退出
  folio 时会立即提交待提交的内容。只提交被保存的文件，提交信息为 *Update <路径>*；
  使用 **提交** 并填写自己的说明可立即提交。
- 打开文件的 **版本**，最新的在前。版本以只读方式按原样打开；**更改** 逐行显示它与当前的
  差异，**并排** 显示两个绘制好的文档（包括图表）。**恢复此版本** 会把它的文本作为未保存的
  修改放入编辑器——是否保存由你决定。
- **在树中**：修改过的文件会被标记，内部有修改的文件夹带一个圆点，项目显示其分支。
- 作者取自仓库配置中的 `user.name` / `user.email`，其次是 `~/.gitconfig`，否则为系统用户。

git 内置于 folio（isomorphic-git，纯 JavaScript），因此在未安装 git 的机器上也能使用。有几项功能需要系统中安装 git，缺少时会提示：更改与 worktree 的审阅（见下文）、暂存更改和撤销提交，以及作为项目打开的 worktree——isomorphic-git 无法读取它，因此那里的更改、历史和行号旁标记通过系统 git 完成。

### 更改

在所有系统上按 `Ctrl+Shift+G`（或右侧栏的提交按钮）打开**更改**面板，如同代码编辑器的源代码管理：
列出工作文件夹中已更改的文件和已暂存待下次提交的文件，每个都带有字母（**A** 新增、**M** 修改、**D** 删除、**U** 未跟踪）。
文件用 `+` 和 `−` 加入或移出暂存区（或从分组标题一次全部操作），用箭头放弃其更改——会先询问，无法撤销——点击文件名即可打开。
填写消息并点击**提交**（或 `Cmd/Ctrl+Enter`）提交已暂存的内容。面板跟随当前显示的文档，磁盘变化时重新查看。
在代码项目中就这样提交：保存不会自动提交。

### 行号栏中的更改与逐行作者

在代码编辑器中编辑的受 git 管理的文件，会在输入时于行号旁标出相对上次提交的更改：绿色竖条表示新增的行，
蓝色表示修改的行，红色缺口表示删除行的位置。点击标记会显示这些行原来的内容，并提供**还原**按钮撤回该更改。
命令中的**逐行作者（blame）**会在行号旁加一列——作者和距今时间，悬停时显示提交消息、作者和日期；再次执行同一命令即可移除。
有系统 git 时使用系统 git，否则由 folio 自己读取文件历史。

### 审阅智能体的工作

folio 适合放在终端里运行的 AI 智能体旁边使用：你主要阅读和审阅它改了什么，偶尔动手修改。

- **审阅**（**更改**面板里的页面按钮、命令，或历史中某个提交的菜单）在标签页中以拉取请求文件的方式打开更改：左侧是文件，右侧是每个文件的更改及三行上下文，未改动的部分折叠，可单栏或双栏，按语言着色，行内改动的词会被标出。工作副本、某个提交、某个提交之后的更改、worktree 相对于其基准——都是同一视图。标为**已查看**的文件会折叠，并保持标记直到其内容改变。在工作副本中，每段更改都可以从其标题暂存、取消暂存或丢弃。双击某一行（或**编辑**）会在审阅旁边打开该文件并定位到这一行进行编辑。审阅跟随磁盘：智能体写入的内容会自动出现，视图中变化的文件会短暂高亮。文件列表可以平铺，也可以按文件夹树显示（列表上方的按钮，选择会被记住）：文件夹在前，只含一个文件夹的文件夹与其合并为一行（`src/http/controllers`），单击可折叠文件夹。
- **自上次查看以来**只显示上次查看之后的变化——编辑以及智能体自己的提交——最新的在前，并标明时间。在其中某个文件上点**已查看**会为它前移查看点，**全部已看**则为全部前移。**更改**面板会统计这些文件。
- **Worktree**（右侧栏的分支按钮）列出仓库的 worktree——智能体或子智能体的，在 `.claude/worktrees` 或其他位置——显示分支、领先和落后于基准的提交、已更改文件和时间。每个都可以相对基准审阅、作为项目打开（其更改、历史和行号旁标记都可用）或在终端中打开、不提交地把更改取到主副本、合并，或连同分支一起删除。项目内部的 worktree 不参与搜索和跳转到文件。
- **评论**：行号旁的 `+` 添加评论；行移动时评论会跟着它的行。**发送给智能体**会把未发送的评论——每条附带文件、行号和周围的行——作为一次粘贴、不带回车地放进智能体所在的控制台：在那里阅读后自己发送。
- **将 Claude Code 连接到 folio**（命令）会在仓库的 `.claude/settings.local.json` 中添加一个钩子（写入前会先展示）：每次编辑后 Claude Code 都会告诉 folio 文件、会话和时间，审阅和 worktree 中会显示谁改了什么。它还会用 Claude Code 自己的 `claude mcp add --scope local` 为该项目把 folio 的 MCP 服务器加入 Claude Code（写入其设置，而非仓库；该命令也会展示，无法运行时 folio 会告诉你要运行什么）。之后代理有四个工具：`show_changes` 打开带有其消息的审阅并等待你的答复——**批准**，或带着你对各行的评论**要求修改**（每条附文件、行号和上下文）；`get_review_comments` 读取尚未交给代理的评论；`open_file` 在某一行打开文件；`list_worktrees` 列出 worktree。folio 未运行时，代理会被告知先启动它。**断开**只移除钩子和服务器，不动其他设置。

审阅需要系统中安装了 git。

### 分支与同步

- **分支**：点击面板中的分支名会打开列表——切换到其他分支，或从当前位置新建分支。
  如果文件中有会被切换覆盖的修改，切换会被拒绝（正在等待暂停的提交会先完成）。
- **远程仓库**：没有远程的文件夹可在面板中填写地址；在 folio 中克隆的仓库
  （**文件 → 克隆仓库…**，或“项目”旁的 ⤓）自带远程，并成为开启了“保存时提交”的项目。
- **同步**会抓取远程、接收远程的提交（快进；若双方都有新提交则生成合并提交），
  再发送你的提交；按钮上显示双向的数量（↑ ↓）。同步前所有修改都需已提交。
- **冲突**会像 git 那样留在文本中：两个版本位于 `<<<<<<<` 与 `>>>>>>>` 行之间，
  面板列出相关文件。编辑它们（在 folio 或任何地方）、保存，然后点击**完成合并**——
  只要还有冲突标记就会被拒绝；**取消合并**会回到你的版本。合并状态按 git 的方式保存
  （`MERGE_HEAD`），系统 git 也能看到；在完成之前，保存不会生成提交。
- **网络**：若已安装系统 git，就通过它——其凭据助手和 SSH 密钥的工作方式与终端中一样
  （它不会在无人可见的终端里询问密码）。没有系统 git 时，folio 自己使用 HTTPS：
  远程要求登录时，面板接收用户名和令牌，由系统加密（Keychain、DPAPI、Secret Service）
  保存在 `folio-data/logins.json` 中——若系统没有加密能力，则只在本次会话中保留。
  同步是你主动执行的操作，不需要文档那样的网络许可。

### 提交图

列表旁有一张类似 Fork 的图：每条开发线一条轨道，合并画成连接轨道的圆环，分支在其基线旁并行并在之后弯回。
**此文件**显示该文件的各个版本，线条穿过未改动该文件的提交（与 `git log -- file` 简化历史的方式相同）；
**所有提交**显示整个仓库——其分支、远程仓库在最近一次抓取时的分支以及标签，名称标在对应提交上，当前检出的提交会被标记。
选择某个提交会打开该文件当时的样子。图由 `@dskripchenko/diagrams`（`renderCommitGraph`）绘制。

## 标签页、表格、比较、导出、设置

**标签页。** `Cmd/Ctrl+Shift+T` 恢复最近关闭的标签页——回到它在标签栏中的位置、原来的视图和滚动位置。标签页可以拖到标签栏的其他位置，拖到视图右半边即在主视图旁打开，拖回左半边则回到主视图。

标签页的菜单可以关闭它本身、其他标签页、右侧的标签页、已保存的标签页或全部标签页（`Cmd/Ctrl+Shift+W`）：先关闭已保存的，再逐个询问有改动的，选择“取消”即停止。标签页可以有自己的颜色，也可以属于一个分组：分组的标签页前有一个带名称和颜色的标签，组内标签页相邻排列，并以该颜色加下划线。单击标签可折叠分组（隐藏其标签页，显示数量）；通过标签页菜单，或把它拖放到分组标签上或组内标签页之间，即可加入分组。分组标签的菜单可以重命名、改色、取消分组或关闭整个分组。颜色和分组保存在会话中。菜单（以及命令面板）中的**在侧边栏中显示**会找到文件所属的项目（或“共享”），展开其文件夹并把该行滚入视野并聚焦：侧边栏折叠时在弹出树中显示，隐藏的项目会被显示出来。

**嵌入文件。** `![[photo.png]]`、`![[clip.mp4]]`、`![[song.mp3]]` 和 `![[report.pdf]]` 在笔记中显示该文件，按文件名在项目任意位置查找（与链接相同）；`![[photo.png|300]]` 或 `|300x200` 指定尺寸。点击图片会在其标签页中打开，指针停在指向图片的链接上会显示它。

**长行**在散文类文本（纯文本、Markdown、日志）中按视图宽度折行，代码中不折行；`Alt+Z`（或命令中的“折行显示长行”）为当前编辑器切换，并为该类文本记住设置。

**PDF** 在其标签页中以 Chromium 自带的查看器打开：页面、缩放、搜索、目录、打印。

**CSV 和 TSV** 以表格显示：自动判断分隔符，表头保持可见，点击列即按该列排序（数字按数值），每次显示一千行；源文本在代码编辑器中编辑。

**比较两个文件**：在文件树中对一个文件选择“选择以进行比较”，再对另一个选择“与……比较”——或在命令中对当前文件使用“将文件与……比较”。显示更改、并排视图或另一文件的渲染效果；“采用其文本”会将其放入编辑器。

**导出。** “导出为 HTML”写出单个页面，图片和图表均嵌入其中，保持 folio 的外观；“导出为 Word (DOCX)”写出标题、强调、链接、列表、引用、代码、表格和图片，图表以图片形式写入。

**提交之外的 git 操作。** 在“更改”中：消息下方的复选框会修改上一次提交（以其消息为起点）；保存按钮会暂存所有更改，包括新文件（stash，以消息命名）——更改下方的列表可将其恢复或删除。在历史中：提交的菜单可以用新提交撤销它（revert）或为其打标签（`v1.2.0 说明` 生成附注标签）；标签随下一次同步推送。分支可在分支菜单中重命名和删除。stash 和 revert 需要安装 git。

**设置**（`Cmd/Ctrl+,` 或设置菜单）：folio 和代码编辑器的所有命令及其按键——“设置按键”会记录按下的按键（以 `Mod` 写入 `keybindings.json`，因此在任何系统上都可用），冲突会被提示；项目的 `.folio/settings.json` 以表单形式编辑，folio 不认识的键会原样保留。

## 语言与欢迎页

folio 开箱即支持英语和俄语：跟随系统语言，或使用设置菜单中所选的语言（立即生效并记住）。所有文本都是 JSON 词典（`src/locales/<code>.json`：`meta`、用于菜单和对话框的 `main`、`window`、`print`）；新增一种语言就是再添加一个这样的文件——放在仓库中，或放在 `folio-data/locales/<code>.json` 中，无需重新构建 folio。文件中缺少的内容使用英语；数字的复数形式按 `Intl.PluralRules` 的顺序写成列表（`["{n} file", "{n} files"]`）。

“folio 能做什么”（命令、帮助菜单、空窗口）会打开一个只读页面，其中各类块都实时绘制；首次启动时会自动打开，使用当前界面语言。

## 未保存的内容与快速笔记

与 Sublime Text 一样：无标题标签页就是快速笔记，未保存的修改不会写入文件。两者都会在你
输入时写入 `folio-data/session/`，因此能经受关闭 folio、崩溃和重启电脑，并原样恢复。有未保存修改的标签页带有一个圆点。关闭这样的标签页时会询问是否保存；关闭
folio 则什么都不问——所有内容都已在磁盘上。如果在你编辑时文件在磁盘上发生了变化，folio
会提示并保留两者：从磁盘取回文件，或者保留你的版本并覆盖保存。快速笔记通过 **保存**
存入“共享”（或任意位置），以其第一行命名。

## 打印

**文件 → 打印**（`Cmd/Ctrl+P`）将当前文档作为文档打印：以阅读而非编辑模式；folio 的侧边栏、标签页、按钮和历史面板不会出现在纸上，
并且无论屏幕是何种主题，纸面始终为浅色。每个部件都以 embed 提供的打印形式输出（`DskEmbed.print.prepare`）：完整的 BPMN 或 DMN 图
（DMN 文件附带其决策表）、draw.io 的所有页面、完整的流程或白板、作为静态文档的 API 参考、以封面和章节呈现的视频、不含控件的看板和日历。
随后会打开系统打印对话框；PDF 通过“导出为 PDF”保存（见下文）。

### PDF

**文件 → 导出为 PDF**（`Cmd/Ctrl+Shift+P`）保存当前文档——按显示的样子，包括未保存的修改；**将文件夹导出为 PDF**
（项目菜单或文件树中文件夹的菜单）把整个文件夹保存为一个 PDF。对话框只询问一次并记住设置：

- 纸张大小（A4、A3、A5、Letter、Legal、Tabloid），纵向或横向，页边距（无、窄、常规、宽）；
- 每页顶部的标题，底部的页码（`3 / 12`）；
- 正文之前带链接的目录；根据标题生成的书签（PDF 大纲，生成带标签的 PDF）；
- 图表的颜色和背景。

文件夹按书的顺序打印：每个文件夹中先是 `index.md` 或 `README.md`，然后按名称排列的文档，再是子文件夹；
每个文档从新的一页开始，图表和 API 文件以文件名作为标题。从一个文档指向另一个文档的链接会变为 PDF 内部的链接。
页面在文档会话的隐藏窗口中排版——网络许可在那里同样有效——每个部件都以其打印形式呈现，然后由 Chromium 打印为 PDF。

## 查找

`Cmd/Ctrl+Shift+F`（**编辑 → 在文件中查找**，或右侧栏的放大镜）在页面旁打开一个面板，搜索文件的文本——全部、“共享”或某个项目——
选项与查找栏相同。匹配一经找到就按文件列出，每行显示其匹配；点击即打开文件，查找栏定位到该匹配。二进制文件、大于 8 MB 的文件
以及“转到文件”排除的文件夹不会被搜索；每个文件最多列出 200 个匹配，总计最多 5 000 个。

过滤器可以缩小搜索的文件范围：`tag:工作`（包括嵌套标签）、`path:notes/`、`file:计划`（加引号的值可以包含空格）；没有其余文本时，单独的过滤器会列出匹配的文件。

查询前的箭头打开**替换**：每个匹配显示将被替换成什么，复选框决定参与的文件，**全部替换**在写入前会带着数量再确认一次。
使用正则表达式时，`$1`、`$&` 等表示其分组；不使用时文本按原样处理。带有未保存更改而打开的文件会被跳过（并给出提示），
以免任一方丢失；未更改的已打开文件会显示新文本。保留历史的文件夹为整个替换生成一个提交——`Replace "a" with "b"`——而不是每个文件一个提交。

`Cmd/Ctrl+K` 或 `F1`（**视图 → 命令**）打开 folio 操作的面板——即菜单和侧栏中的操作——同样按名称查找，每项显示其快捷键；最近使用的排在前面，当前无法执行的（没有打开文档时的保存、已开启的模式）不会列出。

`Cmd/Ctrl+T`（**文件 → 转到文件**）打开一个面板，列出“共享”和可见项目中 folio 能打开的所有文件，随输入的名称排序：
字符按顺序出现即可，不必连续——`rn` 能找到 `release-notes.md`；单词首字母权重最高，名称中的匹配高于文件夹中的匹配。
方向键选择，Enter 打开，Escape 退出。每个文件夹的列表只遍历一次，在其中有文件新增或删除前一直保留；
依赖和构建输出文件夹（`vendor`、`dist`、`build`、`target`、`coverage`……）不在其中，尽管文件树会显示它们。

`Cmd/Ctrl+F`（**编辑 → 查找**）在页面上方打开查找栏：所有匹配都会标出，当前匹配会滚动到可见处；Enter 和 Shift+Enter
在匹配间前后跳转，计数显示当前位置。**Aa** 区分大小写，**ab** 匹配整个单词（任何文字），**.\*** 使用正则表达式。
阅读模式和可视化编辑器搜索绘制出的页面——匹配不会跨段落，页面本身也不会被改动；Markdown 源码搜索其输入框，代码编辑器中的文件搜索其全部文本并在其中标记匹配，
按 Escape 后当前匹配会在其中保持选中；大文件会整体搜索，而不只是可见的行。查找栏下的页面发生变化（编辑、磁盘上的文件被修改）时会重新搜索。

## 控制台

`` Ctrl+` ``（**视图 → 控制台**，或右侧栏的控制台按钮）在页面下方打开一个面板，在“共享”中运行你的 shell——终端启动的 zsh 或 bash，
Windows 上为 PowerShell；项目或文件夹菜单中的**在此打开控制台**会在该文件夹中打开一个。标签页可容纳多个控制台；**+** 在同一文件夹再开一个，
标签上的 × 结束其 shell。全屏程序——`vim`、`htop`、`less`、`mc`——与在终端应用中一样工作，程序请求时支持鼠标；面板高度可拖动顶边调整，
并跟随窗口的浅色或深色主题。在非 Mac 系统上，控制台中的 Ctrl 加字母归 shell 所有（^W、^E、^P……），而不是 folio 的快捷键——Ctrl+F 除外，它在输出中查找。
控制台随窗口一同结束。

对于 zsh、bash 和 PowerShell，folio 会在 shell 启动时稍作补充（在你自己的启动文件照常运行之后）：每条命令的提示符旁出现标记——成功为绿色，失败为红色，运行中闪烁；
悬停可见命令、退出码和耗时；点击即选中其输出。标签显示正在运行的内容和所在文件夹（跟随 `cd`），命令失败或后台标签有输出时显示圆点。
`Cmd+↑`/`Cmd+↓`（非 Mac 为 `Ctrl+Shift+↑`/`↓`）在命令间跳转，`Cmd+K`（`Ctrl+Shift+K`）清屏，`Cmd+D`（`Ctrl+Shift+D`）在旁边再开一个控制台；
在控制台中按 `Cmd+F` 查找其输出。输出中的路径——`src/app.ts:12:3`——按住 Cmd（Ctrl）点击会在 folio 中打开到对应行；从文件树（或系统）拖入的文件会以路径形式输入。
滚轮按行移动输出，一次事件最多三行，无论系统把鼠标滚轮或触控板轻扫加速到多快——长输出可以几行几行地读。标签页像文档标签页一样有颜色和分组（标签页菜单、分组标签的菜单），并可关闭其他、右侧或全部控制台。右键菜单提供复制、粘贴、全选、查找、清屏、拆分、将面板移到页面旁或铺满整个窗口。`FOLIO_SHELL_INTEGRATION=0` 让 shell 按原样启动。由 `@dskripchenko/terminal` 绘制，shell 运行在 `node-pty` 中。

审阅评论会作为一次粘贴发送到控制台（见*审阅智能体的工作*）：folio 只会粘贴到能把粘贴当作整体接收的程序中——zsh、bash 5.1+、PowerShell、智能体的 CLI——并且从不按回车。

## 资源占用、日志、保持唤醒

右侧栏底部的**指示器**显示 folio 占用的内存——主进程、窗口、图形、Chromium 的辅助进程、它启动的语言服务器——下方的进度条以内存上限为满格：超过上限的四分之三变黄，超过上限变红。提示中还显示处理器占用。点击打开**进程**窗口：每个进程的内存和处理器，最近半小时的内存曲线及上限线，用**重新启动**重启语言服务器，用**关闭**关闭控制台。在 folio 控制台中运行的程序（代理、构建）单独列在**控制台中（不计入）**下：它们不属于 folio，不计入其总量和上限。每 15 秒采样一次，窗口打开时每 2 秒一次。

**上限**在设置窗口的**应用**页。folio 的内存上限（默认 4 GB，0 表示不限）是软上限：超过时 folio 释放文件和符号索引及 Chromium 缓存，并重启最重的语言服务器；一分钟后仍超过，则提示占用最多的进程，并提供**重新启动它**、**重新启动 folio** 和**进程**。语言服务器有自己的上限（默认 2 GB）：超过时连同其文件重新启动；基于 Node 的服务器也以此作为堆上限。每个进程的硬堆上限（默认关闭）只是最后手段——达到它的进程会崩溃并丢失未保存的内容——下次启动时生效。

**日志**是 `folio-data/logs/folio-YYYY-MM-DD.log`，每行一个 JSON 对象：启动与退出、应用及其窗口的错误、崩溃或无响应的进程、语言服务器启动、达到上限、保持唤醒的开关，以及每分钟一次的各进程采样——事后可以据此追查变慢的原因。超过保留天数（默认 5 天，设置中可选 1–30）的文件会被删除，崩溃转储（`folio-data/crashes/`，从不上传）一并删除；单日文件达到 50 MB 后续写到 `.1`。日志不含文档内容和令牌。**帮助 → 打开日志文件夹**，以及**保存报告…**——把最近的日志、崩溃转储和版本信息打包成 ZIP 以便发送。代理可以通过 folio 的 MCP 服务器 `get_app_log` 读取日志。

**保持唤醒**——侧栏中的杯子图标或命令面板：直到关闭、1/2/4 小时，或**控制台中有命令运行时**及其后一分钟（依据 shell 集成的标记：正在工作的代理让电脑保持唤醒，回到提示符后允许休眠）；屏幕也保持常亮、不启动屏幕保护程序，除非勾选**允许屏幕熄灭**（会被记住）。支持 macOS、Windows 和 Linux（Linux 上通过桌面环境的抑制接口：GNOME 和 KDE 支持，单纯的窗口管理器可能不支持——此时杯子的提示会说明系统未接受请求）。合上盖子的 Mac 在没有外接显示器和电源时仍会休眠：folio 无法绕过这一点。

### 代理负载下、崩溃之后、机器状态

**folio 节制地跟踪磁盘变化。** 每次变化都要重新计算的内容——文件树的 git 标记、链接/标签/关系图/任务所依据的文件列表——每个仓库或文件夹同一时间最多运行一次；期间发出的请求共享下一次运行，文件夹的文件列表在其内容变化前一直保留。构建产物和工具缓存内部的变化完全不跟踪：`dist`、`build`、`out`、`target`、`vendor`、`coverage`、`.next`、`.nuxt`、`.turbo`、`.cache`、`__pycache__`、`.venv`、`venv`、`.gradle`——代理在构建和测试时会在那里写入成千上万个文件。这些文件夹本身仍会在文件树中出现和消失，展开时列出其文件。项目可以在 `.folio/settings.json` 中设置自己的列表，它将替代默认列表：`"watchExclude": ["generated", "src/gen"]`（名称在任意层级生效，路径从根目录算起）。

**日志会记录哪些操作慢**：窗口请求超过 2 秒（只记名称和耗时，不记路径或文本）、主进程停顿一秒及以上，以及每分钟采样中的事件循环延迟和排队的工作。**进程**窗口也显示主进程的延迟。

**崩溃之后**——上次运行开始后没有正常退出（被系统终止或崩溃）——folio 会在下次启动时提示一次，并提供**打开日志文件夹**和**保存报告…**。

`folio-data` 所在的**磁盘**在启动时及每十分钟检查一次；可用空间少于 5 GB（设置中的**应用**页；0 表示从不）时 folio 会提示，并提供**清除缓存**。**应用**页还显示 `folio-data` 的大小及构成——Chromium 缓存、更新、崩溃转储、日志、未保存内容；**清除缓存**会删除 Chromium 缓存、已下载的更新（保留待安装的那个）和崩溃转储；未保存的内容、审阅标记和设置从不触碰。**使用电池时** folio 每分钟采样一次，而不是每 15 秒。

### 来自控制台的通知

当 folio 不在前台时，系统通知会告知：

- 控制台中运行超过一分钟的命令（**应用**：秒数；0 表示从不）已结束——命令、耗时、是否失败；
- 控制台中的程序请求关注：命令运行期间通过 OSC 9 或 OSC 777 发出的消息，或响铃（每个控制台每 30 秒最多一次）。设置好通知渠道后，Claude Code 会在完成或等待回答时发送它们：在 `~/.claude/settings.json` 中设置 `"preferredNotifChannel": "iterm2"`（消息）或 `"terminal_bell"`（响铃），或在其 `/config` 中的 **Local notifications** 设置。默认值 `auto` 在 folio 的控制台中不会发送任何通知。

点击通知会把 folio 带到前台并定位到该控制台。每个控制台标签的提示显示其程序的内存和处理器占用；程序占用超过 1 GB 的标签会直接显示。超过 8 GB（**应用**；0 表示从不）或处理器连续忙碌五分钟时，folio 会提示并提供**进程**和**关闭控制台**——但自身不做任何操作：那些不是它的程序。

## 数据存放在哪里

Electron 默认把数据存放在用户配置目录中。folio 把所有数据——设置、缓存、会话数据、
日志——都移到程序旁边的 `folio-data/` 中：

| 运行方式 | `folio-data/` 位于 |
|---|---|
| Windows | `folio.exe` 旁边 |
| macOS | `folio.app` 旁边 |
| Linux | `.AppImage` 文件旁边 |
| 设置了 `FOLIO_DATA` | 该目录 |
| 从源码运行 | 工作目录中的 `.folio-data/` |

因此，删除程序所在的文件夹就会删除它写入过的一切。反过来说：该文件夹必须可写——
不要把 folio 解压到只有管理员才能写入的位置。

其中包括：工作区与设置（`workspace.json`）、自定义快捷键（`keybindings.json`）、网络授权（`consent.json`）、加密保存的同步登录信息（`logins.json`）、共享（`library/`）、打开的标签页和未保存的编辑（`session/`）、审阅标记——已查看的文件、评论、上次查看的检查点以及 Claude Code 报告的编辑（`review/`）——自定义语言（`locales/`）、更新（`update/`）、日志以及 Chromium 自身的数据（`chromium/`）。

只有两个文件会写入你的文件夹，而且只在你要求时：设置窗口中的项目设置写入项目的 `.folio/settings.json`；**将 Claude Code 连接到 folio** 会在仓库的 `.claude/settings.local.json`（本地文件，不提交）中添加钩子，并把 folio 的 MCP 服务器加入 Claude Code 对该项目的本地设置——**断开 Claude Code** 会同时移除两者。删除 folio 不会动它们。folio 的 MCP 服务器只监听 127.0.0.1，且只响应保存在 `folio-data/review` 中的令牌。

## 更新

folio 每天启动时查看一次 GitHub 上的最新版本。较新的版本会下载到 `folio-data/update/`，用同一版本旁发布的 `.sha256` 校验后在那里解压；folio 关闭时它会替换程序——`.app` 或 AppImage 被重命名到原位，Windows 上在 folio 退出后把文件复制覆盖到文件夹（不动 `folio-data/`）——也可以在设置里点 **重启并更新** 立即替换。后台不运行任何东西。**检查更新** 立即检查；**每天检查更新** 可关闭每日检查。

校验和证明压缩包就是版本中所列的那个且完整；它经 TLS 来自同一版本，因此不能证明版本由谁发布。这由构建的来源证明负责：`gh attestation verify folio-….zip --repo dskripchenko/folio`。

## 单一窗口

再次启动会把正在运行的 folio 切到前台，而不是启动第二个副本；文档以该窗口的标签页形式打开。
