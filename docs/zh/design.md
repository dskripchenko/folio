# 工作原理

## 两类进程

folio 是一个 Electron 应用，Electron 将它分为两部分：

- **主进程**掌管窗口、菜单、磁盘和网络规则。只有它读写文件。
- **文档窗口**负责绘制文档。它在上下文隔离和 Chromium 沙箱中运行，没有 Node.js，
  并受内容安全策略约束，只允许 folio 自己的脚本。它能向主进程请求的内容都经过一座
  小桥（preload 脚本）——打开、保存、读取项目中的文件——除此之外别无其他。

## 文档能做什么


Markdown 文件可能来自任何地方，因此窗口不信任它：

- 它只能看到打开它的文件夹中的文件（由 folio 自己的协议提供），看不到该文件夹之外的任何内容；
- 只有在你为该文件或文件夹授权后，它才能访问网络——API 参考中的“试一试”、按 URL 加载的图片或视频；
- 它不能把窗口导航到其他页面，也不能打开新窗口；链接会交给系统浏览器打开。

## 打开文档

可以通过 **文件 → 打开**、把文件拖到窗口上、从命令行（`folio notes.md`）打开 Markdown
文件；如果 folio 已在运行，再次带文件启动时会由正在运行的 folio 打开它。指向同一文件夹中
另一个文档的链接会在标签页中打开该文档。重启后，打开过的文档和当前文档都会恢复。

## 共享与项目

工作区分为两部分：**共享**——存放通用文档的一个文件夹（默认是 `folio-data/library`，
也可以选择自己的文件夹）；**项目**——添加到 folio 的任意磁盘文件夹。列表保存在
`folio-data/workspace.json` 中；文件夹本身保持原位。项目或共享中的文档可以读取整个
文件夹的文件；单独打开的文件只能读取它所在的文件夹。

侧边栏显示“共享”和各项目：先是固定的项目，然后按分组，最后是其余项目；项目菜单（右键）
可以固定、重命名、放入分组、隐藏或从 folio 中移除（磁盘上的文件夹保留）。树中列出文件夹和
folio 能打开的文件，文件夹在前，并跟随磁盘变化：在别处新增、修改或删除的文件会立即显示，
打开的文档会重新绘制。`Cmd/Ctrl+B` 可隐藏侧边栏。

## 使用 git 的历史

按文件夹分别设置——“共享”和每个项目——且仅在你需要时启用。作为 git 仓库（或位于其中）的
文件夹会直接显示历史；其他文件夹可以在 **历史** 面板（`Cmd/Ctrl+Shift+H`）中点击
**保留历史** 来开始：在 `main` 分支上创建仓库，并对现有内容做第一次提交。

- **保存时提交**——由 folio 开始的历史默认开启，已有的仓库默认关闭（folio 不会擅自向项目
  提交）。保存的文件会在最后一次保存 3 分钟后提交，因此连续多次保存只产生一次提交；退出
  folio 时会立即提交待提交的内容。只提交被保存的文件，提交信息为 *Update <路径>*；
  使用 **提交** 并填写自己的说明可立即提交。
- 打开文件的 **版本**，最新的在前。版本以只读方式按原样打开；**更改** 逐行显示它与当前的
  差异，**并排** 显示两个绘制好的文档（包括图表）。**恢复此版本** 会把它的文本作为未保存的
  修改放入编辑器——是否保存由你决定。
- **在树中**：修改过的文件会被标记，内部有修改的文件夹带一个圆点，项目显示其分支。
- 作者取自仓库配置中的 `user.name` / `user.email`，其次是 `~/.gitconfig`，否则为系统用户。

git 内置于 folio（isomorphic-git，纯 JavaScript），因此在未安装 git 的机器上也能使用。

### 分支与同步

- **分支**：点击面板中的分支名会打开列表——切换到其他分支，或从当前位置新建分支。
  如果文件中有会被切换覆盖的修改，切换会被拒绝（正在等待暂停的提交会先完成）。
- **远程仓库**：没有远程的文件夹可在面板中填写地址；在 folio 中克隆的仓库
  （**文件 → 克隆仓库…**，或“项目”旁的 ⤓）自带远程，并成为开启了“保存时提交”的项目。
- **同步**会抓取远程、接收远程的提交（快进；若双方都有新提交则生成合并提交），
  再发送你的提交；按钮上显示双向的数量（↑ ↓）。同步前所有修改都需已提交。
- **冲突**会像 git 那样留在文本中：两个版本位于 `<<<<<<<` 与 `>>>>>>>` 行之间，
  面板列出相关文件。编辑它们（在 folio 或任何地方）、保存，然后点击**完成合并**——
  只要还有冲突标记就会被拒绝；**取消合并**会回到你的版本。合并状态按 git 的方式保存
  （`MERGE_HEAD`），系统 git 也能看到；在完成之前，保存不会生成提交。
- **网络**：若已安装系统 git，就通过它——其凭据助手和 SSH 密钥的工作方式与终端中一样
  （它不会在无人可见的终端里询问密码）。没有系统 git 时，folio 自己使用 HTTPS：
  远程要求登录时，面板接收用户名和令牌，由系统加密（Keychain、DPAPI、Secret Service）
  保存在 `folio-data/logins.json` 中——若系统没有加密能力，则只在本次会话中保留。
  同步是你主动执行的操作，不需要文档那样的网络许可。

### 提交图

列表旁有一张类似 Fork 的图：每条开发线一条轨道，合并画成连接轨道的圆环，分支在其基线旁并行并在之后弯回。
**此文件**显示该文件的各个版本，线条穿过未改动该文件的提交（与 `git log -- file` 简化历史的方式相同）；
**所有提交**显示整个仓库——其分支、远程仓库在最近一次抓取时的分支以及标签，名称标在对应提交上，当前检出的提交会被标记。
选择某个提交会打开该文件当时的样子。图由 `@dskripchenko/diagrams`（`renderCommitGraph`）绘制。

## 未保存的内容与快速笔记

与 Sublime Text 一样：无标题标签页就是快速笔记，未保存的修改不会写入文件。两者都会在你
输入时写入 `folio-data/session/`，因此能经受关闭 folio、崩溃和重启电脑，并原样恢复。有未保存修改的标签页带有一个圆点。关闭这样的标签页时会询问是否保存；关闭
folio 则什么都不问——所有内容都已在磁盘上。如果在你编辑时文件在磁盘上发生了变化，folio
会提示并保留两者：从磁盘取回文件，或者保留你的版本并覆盖保存。快速笔记通过 **保存**
存入“共享”（或任意位置），以其第一行命名。

## 编辑

`Cmd/Ctrl+E`（或工具栏上的 **编辑**）可在编辑器与阅读之间切换。编辑器有三种模式：
可视化（像文字处理器一样编辑——工具栏、`/` 菜单，所有块都是实时的）、Markdown 本身，
以及两者并排。文件始终是 Markdown：可视化模式无法容纳的内容（h3 以下的标题、任务列表、
提示框、HTML）按原样保留，图片也保留其相对路径。

| 按键 | |
|---|---|
| `Cmd/Ctrl+N` | 快速笔记 |
| `Cmd/Ctrl+O` | 打开文件 |
| `Cmd/Ctrl+S`、`Cmd/Ctrl+Shift+S` | 保存、另存为 |
| `Cmd/Ctrl+E` | 编辑 / 阅读 |
| `Cmd/Ctrl+W` | 关闭标签页 |
| `Cmd/Ctrl+B` | 侧边栏 |

## 数据存放在哪里

Electron 默认把数据存放在用户配置目录中。folio 把所有数据——设置、缓存、会话数据、
日志——都移到程序旁边的 `folio-data/` 中：

| 运行方式 | `folio-data/` 位于 |
|---|---|
| Windows | `folio.exe` 旁边 |
| macOS | `folio.app` 旁边 |
| Linux | `.AppImage` 文件旁边 |
| 设置了 `FOLIO_DATA` | 该目录 |
| 从源码运行 | 工作目录中的 `.folio-data/` |

因此，删除程序所在的文件夹就会删除它写入过的一切。反过来说：该文件夹必须可写——
不要把 folio 解压到只有管理员才能写入的位置。

## 单一窗口

再次启动会把正在运行的 folio 切到前台，而不是启动第二个副本；文档以该窗口的标签页形式打开。
