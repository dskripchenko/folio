# ADR-006. Ревью работы ИИ-агента: изменения, коммиты, worktree

- Статус: принято автором 2026-11-04; R1–R6 выполнены и выпущены в folio 1.7.0; R7 (MCP) — отдельным решением
- Отступление от плана: правка «в диффе» сделана открытием файла рядом с ревью (двойной щелчок по строке) в редакторе с метками изменений на полях — без нового API code-editor и его релиза
- Дата: 2026-11-04

## Контекст

Основной сценарий автора: рядом с folio в терминале работает ИИ-агент
(Claude Code и подобные), который пишет код сам и через субагентов, часто
каждый в своём git worktree. Человек при этом в основном **смотрит и
ревьюит** изменения и **немного правит** код. Этот сценарий должен быть
главным для folio как лёгкой IDE.

Что уже есть:
- панель изменений: файлы в индексе и без, коммит, откат файла;
- метки изменений на полях редактора;
- история файла с версией, диффом и сравнением рядом;
- blame, stash/amend/revert/теги/ветки;
- консоль с настоящим терминалом (node-pty);
- слежение за файлами.

Чего не хватает:
- **Worktree не видны.** git идёт через isomorphic-git, а он worktree не
  поддерживает (файл `.git` с `gitdir:`). Системный git вызывается только
  для stash и revert.
- **Дифф рассчитан на один файл и только на чтение.** Нет набора изменений
  целиком (рабочая копия, коммит, диапазон коммитов, ветка от базы).
- **Не видно, что изменилось с прошлого просмотра.** Есть только «против
  HEAD», а агент меняет файлы, пока человек смотрит.
- **Замечания нечем вернуть агенту.**

## Решения автора

| № | Вопрос | Решение |
|---|---|---|
| 1 | Работа с git для ревью | **Системный git** для всего, что касается ревью: worktree, диапазоны, дифф наборов, применение фрагментов. isomorphic-git остаётся запасным для простых операций; без установленного git ревью-функции объясняют, чего не хватает. |
| 2 | Экран ревью | **Вкладка «набор изменений»**, как вкладка Files в PR. Слева дерево файлов с отметками «просмотрено». Справа все файлы подряд, в одну колонку или две, с подсветкой синтаксиса и изменённых слов, неизменённые места свёрнуты. Правая сторона редактируемая (code-editor). Действия над фрагментом: в индекс, откатить, замечание. Один экран для рабочей копии, коммита, диапазона и worktree. |
| 3 | Слежение за работой агента | **Контрольные точки «с последнего просмотра»** как основа: она работает с любым агентом. Плюс **хуки Claude Code** по желанию, для привязки изменений к агенту, сессии и субагенту. Разбирать транскрипты не будем. |
| 4 | Worktree | **Панель worktree.** Каждый показан с веткой, отставанием и опережением относительно базы, изменёнными файлами и последней активностью. Действия: ревью относительно базы, открыть как проект, влить, забрать без коммита (squash в рабочую копию), удалить вместе с веткой. `.claude/worktrees/` и подобные исключаются из поиска и индекса основного проекта. |
| 5 | Обратная связь агенту | **Первый этап — вставка в терминал агента**: кнопка «Отправить агенту» отправляет собранные замечания (файл, строки, фрагмент, текст) в выбранную консоль. **Второй этап — MCP-сервер folio**: агент сам просит показать дифф и дождаться решения, получить замечания, открыть файл на строке. |
| 6 | Порядок работы | Как для IDE-трека: **локально до конца плана**, без push, PR, CI и релизов, затем один релиз. |

## Устройство

### R1. Слой git для ревью (`src/main/review/git.ts`)

- Запуск системного `git` через `execFile` с аргументами массивом (без
  оболочки), `-c core.quotepath=false`, `--no-pager`, `LC_ALL=C`; лимит на
  размер вывода; отмена долгих команд.
- `worktrees(repo)`: `git worktree list --porcelain` даёт путь, HEAD, ветку
  и признаки locked/prunable. Для каждого `status --porcelain=v2 -z` и
  `rev-list --left-right --count base...HEAD`.
- `changeset(spec)`, где spec — один из вариантов:
  - `{ kind: 'working', repo }`: индекс и рабочая копия против HEAD, плюс
    неотслеживаемые файлы;
  - `{ kind: 'commit', repo, oid }`: коммит против первого родителя;
  - `{ kind: 'range', repo, from, to }`: диапазон коммитов, `from...to` или
    `from..to`;
  - `{ kind: 'worktree', path, base }`: worktree против базовой ветки
    (merge-base), с незакоммиченным.

  Ответ: список файлов (статус, переименование, бинарный ли, число строк
  `+/-`) и тексты «до» и «после» по запросу (`git show <rev>:<path>`, файл с
  диска). Дифф по строкам считает окно (наш Myers), по словам — внутри
  изменённых строк.
- Применение фрагмента: патч фрагмента строится из текстов и отдаётся в
  `git apply --cached` (в индекс), `git apply -R` (откатить в рабочей
  копии) или `git apply --cached -R` (убрать из индекса). Если патч не лёг,
  показываем ошибку, файл не трогаем.
- Действия с worktree: `worktree remove [--force]` и `branch -D` (с
  вопросом); «влить» — `merge --no-ff` в текущую ветку основной копии;
  «забрать без коммита» — `diff base...branch | git apply --3way` в рабочую
  копию основной; конфликты — штатные метки git, файлы в панели изменений.

### R2. Вкладка ревью (`src/renderer/review/`)

- Вкладка нового вида `review` с адресом набора (spec). Она переживает
  перезапуск через сессию, как обычная вкладка.
- Слева дерево файлов набора: статус, `+/-`, отметка «просмотрено»,
  фильтр «только непросмотренные». Справа лента файлов. Длинный набор
  рисуется лениво: файл раскладывается, когда подходит к видимой области.
- Файл в ленте:
  - заголовок с путём, `+/-` и действиями (открыть файл, просмотрено,
    в индекс или откатить весь файл);
  - вид «одна колонка» или «две колонки», переключается для всей вкладки;
  - неизменённое свёрнуто до трёх строк контекста и раскрывается щелчком;
  - подсветка синтаксиса @dskripchenko/syntax;
  - изменённые слова внутри строки подчёркнуты.
- Правка: в наборе рабочей копии и worktree сторона «после» — это
  code-editor с файлом с диска. Сохранение такое же, как у вкладки файла,
  после него набор пересчитывается. Коммиты и диапазоны только для чтения.
- Для фрагментов в code-editor нужен способ раскрасить строки: фон
  добавленной, удалённой или изменённой и вставленные блоки удалённых
  строк. Если готового API нет, это **минорный релиз code-editor**:
  `setLineClasses`, виджеты между строками.
- Замечание к строке или фрагменту: поле под фрагментом. Замечания
  хранятся в `folio-data/review/<repo-hash>.json` с привязкой к файлу,
  тексту фрагмента и строкам. Если фрагмент сдвинулся, замечание ищется по
  тексту; если фрагмент исчез, оно помечается «устарело».
- Отметки «просмотрено» ставятся на файл и на фрагмент и тоже лежат в
  `folio-data/review`. Ключ — хеш текста фрагмента: фрагмент, который агент
  тронул снова, теряет отметку сам.
- Точки входа:
  - панель изменений: «Ревью изменений»;
  - история: коммит → «Ревью коммита», выделение двух коммитов → «Ревью
    диапазона»;
  - панель worktree;
  - команды.

### R3. Активность и контрольные точки (`src/main/review/activity.ts`)

- Для репозитория в проекте folio следит за файлами (уже есть watcher) и
  ведёт ленту: какой файл, когда и сколько строк. Повторы за короткое время
  склеиваются.
- Контрольная точка — снимок того, что человек видел: для каждого
  изменённого файла хеш и текст на момент «Отметить всё просмотренным» или
  закрытия ревью. Тексты хранятся компактно в `folio-data/review/snapshots`,
  старые вычищаются.
- Набор «с последней точки» (`{ kind: 'since', repo, checkpoint }`) — это
  тексты снимка против текущих. Именно его человек смотрит, пока агент
  работает.
- Строка состояния показывает «изменено с просмотра: N файлов»; щелчок
  открывает этот набор. Открытые вкладки ревью обновляются сами, с
  задержкой, без прыжков прокрутки: новое помечается, а не перерисовывается
  целиком.

### R4. Панель worktree (`src/renderer/worktreesPanel.ts`)

- Панель на правой рейке. Для текущего репозитория она показывает основную
  копию и все worktree. У каждого: имя папки, ветка, `↑n ↓m` относительно
  базы, число изменённых файлов, время последней активности. Если хуки
  подключены (R6), ещё и агент или сессия.
- База по умолчанию — ветка основной копии; её можно сменить в панели.
- Действия: «Ревью относительно базы», «Открыть как проект», «Открыть
  терминал здесь», «Влить», «Забрать без коммита», «Удалить» (с вопросом;
  предупреждение, если есть незакоммиченное).
- Индекс и поиск основного проекта не заходят во вложенные worktree:
  папки, где `.git` — файл, плюс `.claude/worktrees`.

### R5. Замечания агенту — терминал

- «Отправить агенту» в шапке ревью собирает текст и отправляет в выбранную
  консоль. По умолчанию это последняя консоль, где запущен агент; признак —
  её заголовок и процесс через shell integration. Текст содержит для
  каждого замечания `путь:строки`, фрагмент диффа и текст замечания.
- Перед вставкой текст показывается для правки. Вставка идёт как
  bracketed paste, без нажатия Enter: отправляет человек.
- Отправленные замечания помечаются «отправлено», их можно закрыть.

### R6. Хуки Claude Code (по желанию)

- Команда «Подключить Claude Code к folio» добавляет в
  `.claude/settings.local.json` проекта хук `PostToolUse` на
  `Edit|Write|MultiEdit|NotebookEdit`. Он пишет одну строку JSON
  (session_id, agent или субагент, путь, инструмент, время) в локальный
  сокет или файл folio: `folio-data/review/events/<repo-hash>.jsonl`.
  Правка показывается до записи, отключение — той же командой.
- folio читает события и подписывает ими ленту активности и worktree:
  какой агент и сессия, когда. Без хуков всё работает, только без подписей.

### R7. MCP-сервер folio (второй этап)

- Локальный MCP-сервер (stdio через маленький мост или HTTP на localhost
  с токеном), команда подключения добавляет его в настройки агента.
- Инструменты:
  - `show_changes(spec)`: открыть ревью и ждать решения человека
    (принято / замечания);
  - `get_review_comments(repo)`;
  - `open_file(path, line)`;
  - `list_worktrees(repo)`.
- Делается после R1–R6, отдельным решением о готовности.

## Этапы

| Этап | Что | Готово, когда |
|---|---|---|
| R1 | слой git для ревью, исключение worktree из индекса | наборы working/commit/range/worktree собираются; фрагмент в индекс, откат и убрать из индекса работают на Windows/macOS/Linux; модульные тесты на временных репозиториях с worktree |
| R2 | вкладка ревью (+ code-editor, если не хватит API) | e2e: открыть набор, свернуть и развернуть, одна или две колонки, просмотрено, правка и сохранение в диффе, фрагмент в индекс |
| R3 | активность и «с последнего просмотра» | e2e: правка файла извне появляется в наборе «с просмотра»; после отметки — пусто; повторная правка снимает отметку |
| R4 | панель worktree | e2e: два worktree видны со счётчиками; ревью относительно базы; забрать без коммита; удалить |
| R5 | замечания и отправка в терминал | e2e: замечание к фрагменту; отправка вставляет текст в консоль без Enter; замечание переживает сдвиг строк |
| R6 | хуки Claude Code | подключение и отключение правят только `.claude/settings.local.json`; события подписывают ленту |
| R7 | MCP-сервер | отдельным решением после R1–R6 |

После R1–R6: документация на 4 языках, раздел в приветственном документе,
CHANGELOG, один релиз (folio 1.7.0 и, если понадобится, минорный
code-editor).

## Риски

- **Большие наборы** (тысячи файлов, сгенерированные файлы). Нужны ленивая
  раскладка, лимит текста на файл («файл большой — показать?») и бинарные
  файлы без диффа.
- **Агент пишет, пока человек правит тот же файл.** Используем имеющийся
  механизм конфликта вкладки: обе версии остаются, ничего не
  перезаписывается.
- **`git apply` фрагмента** чувствителен к концам строк и пробелам в конце.
  Патч строится из тех же текстов, что показаны; тест на CRLF на Windows.
- **Системный git отсутствует или старый** (worktree с 2.5, porcelain v2 с
  2.11). Проверяем версию один раз и честно сообщаем, чего не хватает.
- **Хуки чужого инструмента** могут поменять формат. Хук пишет только наш
  JSON, а folio переживает его отсутствие и мусор в нём.
- **Вставка в терминал** может уйти не в агента. Поэтому сначала
  предпросмотр, без Enter, и консоль выбирается явно, если угадать не
  удалось.
