# ADR-001. folio — настольное приложение для markdown со всеми виджетами embed

- Статус: принято автором 2026-11-01 (решения — мастер вопросов), план — на согласовании
- Дата: 2026-11-01

## Контекст

`@dskripchenko/embed` рисует в браузере всё, что у нас есть: диаграммы всех
нотаций, OpenAPI/AsyncAPI, BPMN/DMN, draw.io, flow, канбан, календарь, доску,
медиа, markdown с живыми блоками и визивиг-редактор; `markdown-editor` правит
markdown визуально и исходником. Нужна программа на компьютер: открыть
markdown-файл или папку, читать, править, печатать в PDF — на macOS, Windows и
Linux, открытым проектом на GitHub по канонам `portable`.

## Решения автора

| Вопрос | Решение |
|---|---|
| Оболочка | **Electron** (свой Chromium: одинаковое поведение и `printToPDF` на всех трёх ОС) |
| Что открывает | **markdown со всеми блоками; файлы схем напрямую** (.bpmn, .dmn, .drawio, .mmd/.puml/.dot/.d2/…, OpenAPI/AsyncAPI yaml/json); **папку как проект** (дерево, ссылки между .md, относительные пути) |
| Поставка | **portable-архивы без установщика**: zip для Windows и macOS, AppImage для Linux |
| Подпись | **без сертификатов издателя**; подпись происхождения через Sigstore, честное описание Gatekeeper/SmartScreen в README |
| Имя | **folio** (`dskripchenko/folio` свободно; одноимённые мелкие проекты есть — без звёзд) |
| PDF | размер и поля страницы; колонтитулы и номера страниц; оглавление и закладки; папка целиком в один PDF |
| Обновления | **самозамена**, как `portable upgrade`: скачать, сверить, заменить программу в её папке |
| Сеть из документов | **разрешена с согласия**: документ открывается без сети, внешние ресурсы («Попробовать» в OpenAPI, картинки и медиа по URL) — по кнопке «разрешить для файла/папки» |

## Каноны portable, перенесённые на folio

- **Рядом с системой.** Без прав администратора, без реестра и автозапуска.
  Electron по умолчанию пишет настройки в профиль пользователя (`AppData`,
  `~/Library/Application Support`, `~/.config`) — здесь `userData` переносится
  в папку рядом с программой (`folio-data/`): удалил папку — удалил всё.
  Ассоциации файлов не регистрируются (это установщик); открыть файл —
  перетащить на окно/ярлык или `folio путь`.
- **Выпуск собирает CI**, на трёх раннерах; перед публикацией собранная
  программа запускается без среды разработки (Playwright `_electron`: открыть
  файл, отрисовать все виджеты, сохранить PDF).
- **К каждому архиву:** `.sha256`, подпись происхождения Sigstore
  (`gh attestation verify`), отчёт VirusTotal в заметках релиза; бейджи
  tag / release / scanned.
- **Документация** en/ru/de/zh, SECURITY, LICENSE (MIT), CHANGELOG, раздел
  «что не проверено».

## Архитектура

- **Главный процесс** (Node): окна, меню, файловая система, наблюдение за
  файлами, `printToPDF`, обновления. Только он трогает диск.
- **Окно документа**: `contextIsolation`, `sandbox`, без Node в рендерере,
  строгий CSP; доступ к диску — через узкий preload-мост (открыть, сохранить,
  прочитать файл папки проекта). Файлы проекта отдаются по своей схеме
  `folio://` в пределах открытой папки — относительные картинки, медиа,
  вложения работают, выйти за папку нельзя. Ссылки наружу — в системном браузере.
- **Содержимое**: `embed.bundle.js` и стили — внутри программы, без CDN
  (офлайн); `markdown-editor` для правки; виджеты-конструкторы embed — для
  файлов схем.
- **Сеть**: запросы рендерера к внешним адресам блокируются
  (`session.webRequest`), пока для файла или папки не дано согласие;
  согласия хранятся в `folio-data/`.

## PDF

- `webContents.printToPDF`: формат и поля, `displayHeaderFooter` с шаблонами
  колонтитулов (название, дата, «стр. N из M»), `generateDocumentOutline` —
  закладки по заголовкам; оглавление — страница в начале документа.
- Папка в один PDF: документы проекта по порядку (по имени или по списку в
  `folio.json`) собираются в одну страницу печати с разрывами.
- **Печатный вид виджетов — главный объём работы, и он в embed, не в folio**
  (правило «фиксим в пакете-источнике»): сейчас в embed и ките нет ни одного
  `@media print`. Нужен печатный режим каждого виджета: диаграммы и flow —
  SVG целиком, без панелей; OpenAPI/AsyncAPI — документация без «Попробовать»;
  канбан и календарь — таблицы; доска — картинка; BPMN/DMN/draw.io — схема
  целиком; медиа — обложка и ссылка. Это пригодится всем потребителям embed
  (печать страниц Confluence и админки).

## Обновления

Самозамена по образцу `portable upgrade`: релиз с GitHub, сверка `.sha256`
(получена по TLS с того же релиза — честно описать, что это доказывает и что
нет), распаковка рядом, замена при следующем запуске (Windows не даёт заменить
запущенный exe — переименование и подмена при выходе). Без фоновых служб;
проверка новой версии — раз в день при запуске, выключается.

## Честные ограничения (в README)

- Размер: Electron — около 100 МБ в архиве; «максимально лёгкий» здесь —
  без установки, служб и следов в системе, а не по мегабайтам.
- Неподписанное приложение: macOS скажет «нельзя проверить разработчика»
  (открыть через контекстное меню или снять карантин), Windows SmartScreen —
  «неизвестный издатель».
- Linux: AppImage требует FUSE (или `--appimage-extract-and-run`).

## Рабочее пространство и заметки (решения автора, 2026-11-01)

**Рабочее пространство.** Слева — раздел «Общие» (одна папка; по умолчанию
`folio-data/library`, можно указать свою) и список «Проекты» — любые папки на
диске, добавленные в folio; проекты группируются, закрепляются, скрываются.
Документ проекта может ссылаться на общий. Список — `folio-data/workspace.json`;
сами папки остаются, где были, folio их не перемещает.

**Как в Sublime: несохранённое не теряется.**
- Безымянная вкладка — быстрая заметка, без файла; несохранённые правки файла
  не попадают в файл до «Сохранить».
- И то и другое пишется в `folio-data/session/` при каждом изменении (пауза
  около секунды), а не только при закрытии: переживает закрытие окна, сбой и
  перезагрузку системы. При запуске вкладки возвращаются в том же виде —
  заметки, правки, положение курсора и прокрутки.
- Закрыть вкладку с правками — спросить; закрыть приложение — не спрашивать
  ничего (горячий выход): всё и так на диске.
- Файл изменился на диске, пока в folio есть несохранённые правки, — показать
  оба варианта, ничего не перезаписывать молча.
- Заметку позже «Сохранить как…» в «Общие» или в проект.

Буферы — этап 3 (правка), список открытых документов и его восстановление —
этап 1.

## Git: история, по желанию (решения автора, 2026-11-01)

Плотная, но необязательная интеграция: включается для проекта (или «Общих»);
папка, которая уже репозиторий, подхватывается сама; не репозиторий — по кнопке
«Вести историю» (`git init`). Глобальный выключатель — в настройках.

- **Движок:** встроенный isomorphic-git (чистый JS) — история работает на любой
  машине без установленного git, по канону portable; если в системе есть git,
  синхронизация с удалённым идёт через него (его SSH-ключи и менеджер учётных
  данных уже настроены). Без системного git синхронизация — по HTTPS с токеном.
- **Коммиты:** автокоммит на «Сохранить», серия сохранений одного файла за
  несколько минут сливается в один коммит; плюс «Зафиксировать с
  комментарием». Автор коммитов — из настроек git, иначе из настроек folio.
  Несохранённое (горячий выход) в историю не попадает — только сохранённое.
- **В первой версии:** история файла и сравнение версий (текст и отрисованный
  документ со схемами), возврат версии; статус в дереве (изменён/новый/удалён,
  ветка у проекта); синхронизация (pull/push, клонировать репозиторий как
  новый проект, конфликты — в тексте); ветки (создать/переключить).

## Как документ видит файлы (этап 1)

Интерфейс и файлы документов отдаёт одна своя схема `folio://app/`:
`folio://app/ui/…` — сам folio, `folio://app/r/<корень>/<путь>` — файлы корня
(«Общие», проект или папка отдельно открытого файла). Один источник — у
документа работают и картинки, и `fetch` спецификации по относительному пути;
обработчик схемы отдаёт файл только из зарегистрированного корня (с проверкой
через realpath — ссылки наружу не проходят). Сеть: все http(s)-запросы окна
проходят через `session.webRequest` и отменяются, пока для файла или папки
активного документа нет согласия (`folio-data/consent.json`); окно получает
список заблокированных адресов и показывает плашку «разрешить для файла/папки».

## Не делаем в 1.0

Совместную правку (доска — локальная, из блока markdown), облако и
синхронизацию, плагины сторонних виджетов, мобильные версии, установщики.
