# ADR-002. folio как лёгкая IDE: свой редактор кода и инструменты вокруг него

- Статус: принято автором 2026-11-03
- Дата: 2026-11-03

## Контекст

folio 1.0.0 уже умеет многое из того, что ждут от редактора кода: вкладки и
два документа рядом, переход к файлу по имени, палитра команд, поиск и замена
по папке, консоли с shell integration и ссылками на файлы, история git с
ветками, синхронизацией и слиянием. Просмотр кода (`src/renderer/code.ts`) —
подсветка `@dskripchenko/syntax`, проверка данных, сворачивание, логи на сотни
мегабайт с отрисовкой только видимых строк.

Не хватает главного: **правка кода — это `textarea`** (`source-editor` в
`src/renderer/formats.ts`). В режиме правки нет ни подсветки, ни номеров строк,
ни отступов, ни сворачивания; правка ограничена 5 МБ. Вокруг редактора не
хватает и инструментов: git заточен под заметки (автокоммит на сохранение),
дерево и поиск не знают `.gitignore`, нет структуры файла и перехода к
символу, нет запуска задач и панели проблем.

Цель — лёгкая IDE в том же продукте: открыть репозиторий, править код с
удобством обычного редактора, видеть изменения относительно git, запускать
скрипты проекта. Не цель — заменить VS Code/PhpStorm: отладчик, удалённая
разработка и сторонние расширения остаются за рамками.

## Решения автора

| Вопрос | Решение |
|---|---|
| Направление | folio растёт в лёгкую IDE, порядок — ниже в плане этапов |
| Редактор кода | **свой**, не CodeMirror/Monaco — по канону остальных пакетов (diagrams, math, terminal, syntax) |
| Где живёт редактор | отдельный общий пакет **`@dskripchenko/code-editor`** (репозиторий `dskripchenko/code-editor`), без зависимостей кроме `@dskripchenko/syntax`; в пакете — ни слова о folio |
| Форма пакета | ядро без фреймворка (класс `CodeEditor` на DOM-элементе) + веб-компонент `<dsk-code-editor>`; Vue-обёртка — при первом потребителе на Vue |
| Ввод | **EditContext API** там, где он есть (Chromium — значит, весь folio), скрытая `textarea` — запасной путь для Firefox/Safari; `contenteditable` не используем |
| Подсветка при наборе | инкрементальная: состояние токенайзера в конце каждой строки, после правки — заново до строки, где состояние совпало с прежним; требует нового API в `syntax` (0.5.0) |
| Несколько курсоров | в модели с первого дня (выделение — массив диапазонов), в интерфейсе — в этапе E3 |
| Перенос строк | по умолчанию выключен (код), включается; модель высот строк учитывает перенос |
| Git для кода | вид проекта **«код»**: без автокоммита, панель изменений с индексом и коммитом; заметки остаются как есть |
| LSP | **отдельный ADR-003** после E1–I3; в этом ADR — только точки подключения |
| Клавиши | как в VS Code: «перейти к строке» — `Ctrl+G` на всех ОС; на macOS `Cmd+G` — следующее совпадение, на Windows/Linux — `F3`/`Shift+F3` |


## Редактор: `@dskripchenko/code-editor`

### Устройство

- **Модель документа** — массив строк (до десятков МБ этого хватает; piece
  table — если упрёмся). Правка — транзакция: список изменений
  `{from, to, insert}` + новое выделение. Позиции и диапазоны через изменения
  отображаются (`mapPos`) — на этом держатся курсоры, метки, складки,
  диагностики.
- **История** — отмена/повтор транзакциями, слияние подряд набранных символов
  (по времени и виду правки), выделение восстанавливается вместе с текстом.
- **Ввод** — EditContext получает текст, композицию (IME, мёртвые клавиши,
  китайский/японский ввод), выделение; клавиши-команды — через раскладку
  клавиш (keymap) до ввода. Буфер обмена — свои `copy/cut/paste`, вставка
  нескольких строк в несколько курсоров по одной.
- **Отрисовка** — только видимые строки плюс запас (как в `code.ts` и
  `terminal`), абсолютное позиционирование, моноширинный шрифт: ширина знака
  измеряется один раз, широкие знаки (CJK, эмодзи) и табы — по таблице.
  Строки рисуются из токенов `syntax`, номера и метки — отдельной колонкой.
  Очень длинная строка (минифицированный код) рисуется кусками по видимой
  ширине.
- **Подсветка** — `IncrementalHighlighter` из `syntax` 0.5.0 (не построчный
  `tokenizeLine`: многострочные конструкции грамматик сделаны одним
  регулярным выражением, перевод на состояния переписал бы почти все
  грамматики). Состояние берётся на первой границе совпадения в начале
  каждой строки; правка разбирается окном строк заново до строки, где
  состояние совпало. Вывод тождествен полной подсветке (свойство-тест).
  Видимое — синхронно, дальше — догадка и доводка в простое.
- **Оформление (decorations)** — общий механизм для всего, что рисуется
  поверх текста: метки на полях (git, ошибки, точки останова не нужны),
  подчёркивания (диагностики), фон диапазонов (совпадения поиска, парные
  скобки), виджеты между строками (позже — inline-diff). Всё через `mapPos`
  живёт при правке. На нём строятся интеграции folio — пакет про git и LSP
  ничего не знает.
- **Темы** — те же токены и CSS-переменные, что `THEME_CSS` у `syntax`;
  светлая/тёмная — по `data-theme` или системе.
- **Доступность** — EditContext отдаёт текст и выделение экранному диктору;
  роль `textbox`, `aria-multiline`, объявление номера строки.

### Возможности

- Номера строк, подсветка текущей строки, парные скобки — подсветка и
  автозакрытие (скобки, кавычки, с пропуском закрывающей при наборе).
- Отступы: Tab/Shift+Tab по выделению, автоотступ после `{`/`:`/тега,
  выравнивание закрывающей скобки, умный Backspace по отступу; табы или
  пробелы и ширина — из `.editorconfig`, иначе угадываются по файлу.
- Сворачивание из `foldRanges` (`syntax`) — живое при правке.
- Проверка (`validate`) — при паузе в наборе, метки и подчёркивания.
- Строки: закомментировать (`Cmd/Ctrl+/`, блоком — `Shift+Alt+A`),
  переместить (`Alt+↑/↓`), дублировать (`Shift+Alt+↑/↓`), удалить
  (`Cmd/Ctrl+Shift+K`), объединить.
- Несколько курсоров: `Alt+клик`, `Cmd/Ctrl+D` — следующее вхождение,
  `Cmd/Ctrl+Shift+L` — все вхождения, вертикальное выделение (`Alt+Shift`
  мышью/стрелками).
- Перейти к строке и колонке.
- Поиск и замена — API для внешней строки поиска (folio — `findBar`) и
  свой простой вариант для потребителей без неё.
- Слова для автодополнения: API источников подсказок (`completion`) с
  выпадающим списком; встроенный источник — слова документа.
- Конец строки (LF/CRLF) и финальный перевод строки — сохраняются, как были
  в файле, или по `.editorconfig`.
- Размер: правка без потолка в 5 МБ — цель 50 МБ / 1 млн строк; набор с
  задержкой меньше кадра на файле в 100 тыс. строк.

### Проверка

- vitest — модель, транзакции, `mapPos`, история, команды, отступы,
  инкрементальная подсветка (сверка с полной подсветкой после случайных
  правок — свойство, тысячи прогонов).
- **Playwright в настоящем Chromium обязателен** (урок визивига: jsdom не
  видит реального ввода) — набор, IME-композиция (через CDP
  `Input.imeSetComposition`), буфер обмена, несколько курсоров, прокрутка
  большого файла; WebKit/Firefox — для запасного пути через `textarea`.
- Замер производительности в CI (набор и прокрутка на файле 100 тыс. строк)
  с порогом.

## Инструменты folio вокруг редактора

### I1. Проект «код»

- Вид проекта — «заметки» (как сейчас) или «код»; угадывается по признакам
  (`package.json`, `composer.json`, `go.mod`, `Cargo.toml`, `pyproject.toml`,
  `.git` без `.md` в корне…), меняется в меню проекта.
- **`.gitignore`** (и `.git/info/exclude`, глобальный excludesfile) в дереве,
  индексе файлов, поиске по папке и наблюдателе — вместо жёстких списков
  `SKIP`/`NOT_INDEXED`/`node_modules` (они остаются для папок без git).
- **Git в проекте «код»**: автокоммит выключен; панель «Изменения» —
  изменённые файлы, индекс (добавить/убрать файл, позже — кусок), сообщение
  и коммит, отменить изменения файла; на полях редактора — метки
  добавленных/изменённых/удалённых строк относительно HEAD с просмотром
  куска и откатом; авторство строк (blame) — по команде, сбоку.
- isomorphic-git остаётся движком; если на больших репозиториях статус или
  blame окажутся медленными — через системный git, как синхронизация.

### I2. Навигация по коду

- **Символы файла** без внешних инструментов: правила в грамматиках `syntax`
  (объявления функций, классов, методов, констант) → `symbols(text, language)`;
  в folio — оглавление для кода (как у Markdown), переход к символу
  `Cmd/Ctrl+Shift+O`, хлебные крошки над редактором.
- **Символы проекта** `Cmd/Ctrl+Alt+O` — индекс символов в главном процессе
  рядом с индексом файлов.
- Автодополнение по словам файла и проекта.

### I3. Задачи и проблемы

- Задачи проекта: скрипты `package.json`, `composer.json`, цели `Makefile`,
  `justfile`; запуск в консоли folio, последние — сверху в палитре.
- Панель «Проблемы»: разбор вывода задачи по известным форматам (tsc, eslint,
  phpstan, psalm, pest/phpunit, pint, gcc/clang, go, rustc, pytest — общий
  вид `путь:строка:колонка сообщение`) → список с переходом и метками в
  редакторе.
- Форматирование при сохранении внешней командой (prettier, pint, gofmt,
  ruff…) — по настройке проекта, только если инструмент есть в проекте.

### Мелкое

- Настройки проекта в `.folio/settings.json` (вид, отступы, задачи,
  форматирование) — по желанию, в репозиторий коммитится пользователем.
- Клавиши: `Cmd/Ctrl+G` сейчас — «следующее совпадение»; меняется по
  решению автора (таблица выше).
- Переназначение клавиш — файл `folio-data/keybindings.json`, без интерфейса
  в первой версии.

## Не делаем

Отладчик (DAP), удалённую разработку (ssh, контейнеры), сторонние
расширения, встроенные языковые серверы в архиве folio (LSP в ADR-003 —
только найденные в системе), ИИ-дополнение.

Оценка: E1 — самый большой и рискованный (L: ввод и IME), E2 — M (меняет

сразу становится доступен и остальным потребителям (embed и дальше).

## Риски

- **EditContext** — молодой API: поведение с IME на Windows/Linux проверять
  руками на машине автора, держать запасной путь через `textarea` рабочим, а
  не номинальным.
- **Построчное состояние `syntax`** — грамматики с многострочными
  конструкциями (heredoc, шаблонные строки, вложенные языки) могут не
  сводиться к сравнимому состоянию; тогда — повторная подсветка до конца
  видимой области и в простое, а не до совпадения.
- **Объём**: редактор — это много мелких ожиданий пользователя. Список
  возможностей E3 — потолок 0.1.0, остальное — по мере жалоб из
  повседневной работы.
