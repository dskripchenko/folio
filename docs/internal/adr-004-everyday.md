# ADR-004. Повседневные пробелы folio

- Статус: принято автором 2026-11-04
- Дата: 2026-11-04

## Контекст

После 1.3 (просмотр медиа) разобрали, чего в folio явно не хватает: по
командам, документации и IPC, с проверкой по коду. Автор взял в работу всё
найденное, кроме уже отложенного в ADR-003 и исключённого в ADR-002.

## Решения автора

| № | Вопрос | Решение |
|---|---|---|
| 1 | PDF внутри folio | встроенный просмотрщик Chromium: `plugins: true` только для окна документов; без зависимостей |
| 2 | Экспорт | HTML одной страницей **и** DOCX — свой небольшой писатель DOCX на TypeScript в folio (php-docx — PHP, в Electron не годится) |
| 3 | Порядок работы | локально до конца: ветки и тесты на машине, без push/CI/выпусков; затем один заход — `code-editor` → folio 1.4 |

## Объём и этапы

| № | Этап | Что | Готово, когда |
|---|---|---|---|
| D1 | Вкладки и вложения | вернуть закрытую вкладку (`Cmd/Ctrl+Shift+T`, история закрытых); перетаскивание вкладок (порядок, в соседнюю панель); `![[картинка.png]]`, `![[видео.mp4]]`, `![[звук.mp3]]` — встраивание медиа синтаксисом Obsidian (с размером `![[a.png\|300]]`) | e2e |
| D2 | Перенос строк | `code-editor`: мягкий перенос (`lineWrapping`) — визуальные строки, координаты, курсор по визуальным строкам (Home/End/↑/↓), гуттер; folio: `Alt+Z` и настройка (по умолчанию — для текста и Markdown-исходника, не для кода) | браузерные тесты пакета + e2e |
| D3 | Просмотр | CSV/TSV таблицей (шапка закреплена, сортировка по столбцу, разделитель угадывается, большой файл — постранично), исходник — в правке; сравнить два любых файла (из дерева «Сравнить с…», из палитры) — тот же вид сравнения, что у версий | e2e |
| D4 | Git | stash (сохранить, список, применить, вытолкнуть, удалить); исправить последний коммит (amend); отменить коммит (revert) из графа; удалить и переименовать ветку; теги (создать на коммите, список, отправить при синхронизации) | модульные на isomorphic-git + e2e |
| D5 | PDF | `*.pdf` во вкладке через просмотрщик Chromium; ссылки на PDF из заметок — туда же | e2e |
| D6 | Экспорт | «Экспорт в HTML»: одна страница, стили folio, схемы — встроенный SVG, картинки — data:; «Экспорт в DOCX»: заголовки, абзацы с выделением, списки, цитаты, таблицы, код, картинки, ссылки; схемы — картинками (PNG из отрисованного SVG) | модульные (структура DOCX) + e2e; файл открывается в Word/LibreOffice |
| D7 | Настройки | окно настроек: клавиши (список команд, поиск, переназначение, конфликты, сброс) поверх `keybindings.json`; настройки проекта (`.folio/settings.json`: вид, отступы, форматирование, задачи, языковые серверы) | e2e |
| R | Выпуск | документация ×4, CHANGELOG; `code-editor` 0.4.0 → folio 1.4.0 | CI зелёный на трёх системах |

## Риски

- **Перенос строк** — самый сложный этап: у строк появляется разная высота,
  а `code-editor` считает координаты из одной высоты строки (прокрутка,
  `posAtCoords`, сворачивание, виртуальная отрисовка). Нужна карта «строка
  документа → визуальные строки», пересчитываемая по ширине; для очень
  больших файлов — лениво.
- **PDF-плагин** расширяет поверхность окна. Он включается только для окна
  документов; PDF Chromium сам по себе в песочнице, как в Chrome.
- **DOCX** — свой писатель: только перечисленное, без стилей Word сверх
  базовых; проверка — открытие в LibreOffice в тестах, если он есть на машине.
