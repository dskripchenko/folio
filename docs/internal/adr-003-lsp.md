# ADR-003. Языковые серверы (LSP) в folio

- Статус: принято автором 2026-11-03 (решения 1–6 — как предложено)
- Дата: 2026-11-03

## Контекст

После ADR-002 folio правит код своим редактором (`@dskripchenko/code-editor`):
подсветка, сворачивание, команды правки, символы файла и проекта по
шаблонам `syntax`, задачи и панель «Проблемы» из их вывода, форматирование
при сохранении. Чего нет — понимания кода: дополнение знает только слова и
имена символов, перехода к определению нет, ссылок и переименования нет,
ошибки видны только после запуска задачи.

Это даёт Language Server Protocol: сервер языка (`typescript-language-server`,
`intelephense`/`phpactor`, `gopls`, `rust-analyzer`, `pyright`, `clangd`…)
отвечает по JSON-RPC на стандартные запросы. ADR-002 оставил LSP сюда и
зафиксировал рамку: **серверы не входят в архив folio — только найденные в
системе или в проекте**.

## Решения автора

| № | Вопрос | Решение |
|---|---|---|
| 1 | Где живёт клиент LSP | в **главном процессе folio** (`src/main/lsp/`): процессы серверов, JSON-RPC по stdio, свой минимальный слой протокола без внешних зависимостей; окно получает возможности через IPC. Отдельный пакет — когда появится второй потребитель |
| 2 | Что знает редактор | `code-editor` получает **общие точки** без слова «LSP»: подсказка при наведении (`hover`), переход к определению (`F12`, `Cmd/Ctrl+щелчок`), подсказка параметров, переименование (`F2`), действия (`Cmd/Ctrl+.`); дополнение и диагностики уже есть (`completion`, `setDiagnostics`) |
| 3 | Доверие | серверы **из PATH** запускаются сами при открытии файла языка; серверы **из проекта** (`node_modules/.bin`, `vendor/bin`) — только после вопроса «доверять проекту?» один раз на проект (это запуск кода проекта, как задача) |
| 4 | Какие языки сразу | TypeScript/JavaScript, PHP, Python, Go, Rust, C/C++ — по известным командам; любой другой — своей командой в `.folio/settings.json` (`"lsp": { "<язык>": ["команда", "аргументы"] }`), там же выключение |
| 5 | Объём первой поставки | всё сразу, этапами внутри: L1 инфраструктура + диагностики + наведение + определение; L2 дополнение + параметры; L3 ссылки + переименование + действия + форматирование; L4 символы через сервер там, где он есть |
| 6 | Клавиши | как в VS Code: `F12` / `Cmd/Ctrl+щелчок` — определение, `Shift+F12` — ссылки, `F2` — переименовать, `Cmd/Ctrl+.` — действия, `Ctrl+Space` — дополнение, `Cmd/Ctrl+Shift+Space` — параметры |

## Устройство

### Серверы и их жизнь

- **Поиск сервера** для языка файла: сначала настройка проекта
  (`.folio/settings.json` → `lsp`), затем бинарник проекта
  (`node_modules/.bin/typescript-language-server`, `vendor/bin/phpactor`,
  `.venv/bin/pyright-langserver`…), затем PATH. Не нашёлся — молча работает
  то, что есть сейчас (шаблоны `syntax`), в строке состояния — отметка «без
  языкового сервера» с подсказкой, что поставить.
- **Один сервер на (корень проекта, язык)**: запускается при открытии
  первого файла этого языка в редакторе, `initialize` с `rootUri` проекта и
  возможностями клиента; останавливается (`shutdown` + `exit`) через
  несколько минут после закрытия последнего такого файла и при выходе из folio.
- **Падение** — перезапуск с нарастающей паузой, после трёх подряд — отметка
  в строке состояния и журнал вывода сервера (stderr) в отдельной вкладке
  консоли по команде.

### Синхронизация текста

- `didOpen` / `didClose` по вкладкам; `didChange` — **инкрементально**:
  транзакции редактора уже несут изменения диапазонами, смещения редактора —
  UTF-16, как требует LSP по умолчанию (`positionEncoding: utf-16`).
- `didSave` при сохранении; изменения файлов на диске вне folio (watcher) —
  `workspace/didChangeWatchedFiles`.
- Версия документа растёт с каждой транзакцией; ответы на устаревшую версию
  отбрасываются.

### Возможности

| Возможность | Запрос | В редакторе / folio |
|---|---|---|
| Диагностики | `textDocument/publishDiagnostics` | `setDiagnostics(list, 'lsp')`, и в панели «Проблемы» отдельной группой |
| Наведение | `textDocument/hover` | всплывающая подсказка (markdown сервера — рисуется как Markdown folio) |
| Определение | `textDocument/definition` | переход, в другом файле — открыть в редакторе; несколько — выбор в палитре |
| Дополнение | `textDocument/completion` (+ `completionItem/resolve`) | источник `completion` редактора вместе со словами и символами проектов; `textEdit` и сниппеты — простые плейсхолдеры `$1` |
| Параметры | `textDocument/signatureHelp` | подсказка над курсором после `(` и `,` |
| Ссылки | `textDocument/references` | список в палитре с переходом |
| Переименование | `textDocument/prepareRename` + `rename` | поле над словом; `WorkspaceEdit` применяется к открытым вкладкам транзакциями (одна отмена на вкладку) и к закрытым файлам — записью на диск |
| Действия | `textDocument/codeAction` | список под курсором, применение `WorkspaceEdit` / команды |
| Форматирование | `textDocument/formatting` | при сохранении, если проект просит (`formatter: "lsp"`), иначе — внешний инструмент как сейчас |
| Символы | `textDocument/documentSymbol`, `workspace/symbol` | оглавление, крошки и `Cmd/Ctrl+Shift+O` / `Cmd/Ctrl+Alt+O` — от сервера, где он есть; шаблоны `syntax` — запасной путь |

### Чего не делаем

Отладчик (DAP), семантическую подсветку (`semanticTokens`) в первой поставке —
подсветка остаётся у `syntax`; inlay hints и code lens — позже, по жалобам;
установку серверов из folio.

## Тестирование

- Модульные: кодек JSON-RPC (заголовки `Content-Length`, частичные сообщения,
  несколько в одном куске), отображение позиций UTF-16 ↔ смещения, применение
  `WorkspaceEdit` (несколько правок в файле, создание и переименование файлов).
- **Поддельный сервер** в тестах (скрипт на Node, отвечает по сценарию) — e2e
  всех возможностей без настоящих серверов и сети.
- Смоук на настоящих: `typescript-language-server` на folio, `intelephense`
  или `phpactor` на core, `gopls` / `rust-analyzer` — если стоят на машине.

## План этапов

| № | Этап | Готово, когда |
|---|---|---|
| L1 | JSON-RPC и процессы серверов, поиск, доверие проекту, синхронизация текста; диагностики, наведение, определение; в `code-editor` — `hover` и переход к определению | e2e с поддельным сервером; смоук на folio с TS-сервером |
| L2 | Дополнение от сервера, подсказка параметров; в `code-editor` — подсказка параметров, плейсхолдеры | дополнение членов объекта в TS работает |
| L3 | Ссылки, переименование (по всем файлам), действия, форматирование сервером | переименование символа по проекту отменяется во вкладках |
| L4 | Символы от сервера в оглавлении, крошках и переходах; строка состояния и журнал сервера | смоук на core и php-pdf |

## Риски

- **Серверы разные**: возможности смотрим по `capabilities` из `initialize`,
  не по имени сервера; чего сервер не умеет — не показываем.
- **Тяжёлые серверы** (rust-analyzer, TS на больших монорепо): запуск лениво,
  остановка в простое; folio не ждёт сервер — без ответа работает как сейчас.
- **Доверие**: сервер из проекта — исполнение кода проекта; отсюда вопрос
  один раз на проект (решение 3).
- **Объём**: LSP — широкий протокол; берём только перечисленное, остальное — по
  жалобам из повседневной работы.
