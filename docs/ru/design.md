# Как устроено

## Два вида процессов

folio — приложение на Electron, и Electron делит его на две части:

- **Главный процесс** владеет окнами, меню, диском и правилами сети. Только он
  читает и пишет файлы.
- **Окно документа** рисует документ. Оно работает с изоляцией контекста и
  песочницей Chromium, без Node.js, под политикой безопасности содержимого,
  которая разрешает только скрипты самого folio. Что оно может попросить у
  главного процесса, проходит через маленький мост (скрипт preload) — открыть,
  сохранить, прочитать файл проекта — и больше ничего.

## Что может документ


Markdown-файл может прийти откуда угодно, поэтому окно ему не доверяет:

- он видит файлы папки, из которой открыт, — их отдаёт своя схема folio, — и
  ничего за пределами этой папки;
- в сеть — «Попробовать» в справочнике API, картинка или видео по адресу — он
  ходит только после того, как вы разрешили это для файла или папки;
- он не может увести окно на другую страницу или открыть новые окна; ссылка
  открывается в системном браузере.

## Как открыть документ

Markdown-файл открывается через **Файл → Открыть**, перетаскиванием на окно, из
командной строки (`folio notes.md`) или — если folio уже запущен — повторным
запуском с файлом: его откроет работающий folio. Ссылка на другой документ той
же папки открывает его во вкладке. Открытые документы и активный возвращаются
после перезапуска.

## Общие и проекты

Рабочее пространство из двух частей: **Общие** — одна папка для документов,
общих для всего (по умолчанию `folio-data/library` или папка на ваш выбор), и
**проекты** — любые папки на диске, добавленные в folio. Список лежит в
`folio-data/workspace.json`; сами папки остаются, где были. Документ проекта или
«Общих» может читать файлы всей этой папки; отдельно открытый файл — своей папки.

Боковая панель показывает «Общие» и проекты: сначала закреплённые, потом по
группам, потом остальные; меню проекта (правая кнопка) закрепляет его,
переименовывает, кладёт в группу, скрывает или убирает из folio (папка на
диске остаётся). Деревья показывают папки и файлы, которые folio открывает,
папки первыми, и следят за диском: файл, добавленный, изменённый или удалённый
в другом месте, виден сразу, а открытый документ перерисовывается.
`Cmd/Ctrl+B` прячет панель.

## История в git

Для каждой папки отдельно — «Общих» и каждого проекта — и только по желанию.
Папка-репозиторий git (или папка внутри него) показывает историю сразу; другая
заводит её кнопкой **Вести историю** на панели **История** (`Cmd/Ctrl+Shift+H`):
репозиторий на ветке `main` и первый коммит того, что в папке есть.

- **Фиксировать при сохранении** — включено для истории, заведённой folio, и
  выключено для уже существующего репозитория (folio не коммитит в чужой
  проект сам). Сохранённый файл фиксируется через 3 минуты после последнего
  сохранения, так что серия сохранений даёт один коммит; при выходе из folio
  ожидающее фиксируется сразу. Фиксируется только сохранённый файл, с
  сообщением *Update <путь>*; **Зафиксировать** со своим сообщением делает это
  сразу.
- **Версии** открытого файла, новые сверху. Версия открывается только для
  чтения, как была; **Изменения** показывают разницу с текущей построчно,
  **Рядом** — два отрисованных документа, со схемами. **Вернуть эту версию**
  кладёт её текст в редактор как несохранённую правку — сохранять или нет,
  решаете вы.
- **В дереве**: изменённые файлы помечены, папка с изменениями внутри — точкой,
  у проекта видна ветка.
- Автор — `user.name` / `user.email` из конфигурации репозитория, затем из
  `~/.gitconfig`, иначе пользователь системы.

git встроен в folio (isomorphic-git, чистый JavaScript), поэтому всё это
работает там, где git не установлен. Дальше — ветки, pull и push, клонирование
репозитория как проекта (этап 4b) и граф коммитов (4c).

## Несохранённое и быстрые заметки

Как в Sublime Text: безымянная вкладка — быстрая заметка, а несохранённая правка
не попадает в файл. И то и другое пишется в `folio-data/session/` по ходу
набора, поэтому переживает закрытие folio, сбой и перезагрузку компьютера и
возвращается в том же виде. Вкладка с несохранёнными правками помечена точкой.
Закрытие такой вкладки спрашивает, сохранить ли; закрытие folio не спрашивает
ничего — всё уже на диске. Если файл изменился на диске, пока вы правили,
folio говорит об этом и хранит оба варианта: взять файл с диска или оставить
свою версию и сохранить её поверх. Быструю заметку **Сохранить** кладёт в
«Общие» (или куда угодно), с именем по её первой строке.

## Правка

`Cmd/Ctrl+E` (или **Править** на панели) превращает документ в редактор и
обратно. У редактора три режима: визуальный (правка как в текстовом
процессоре — панель инструментов, меню `/`, все блоки живые), сам Markdown и
оба рядом. Файл остаётся Markdown: то, что визуальный режим не держит
(заголовки ниже h3, чек-листы, выноски, HTML), сохраняется как написано, а
картинки сохраняют свои относительные пути.

| Клавиши | |
|---|---|
| `Cmd/Ctrl+N` | быстрая заметка |
| `Cmd/Ctrl+O` | открыть файл |
| `Cmd/Ctrl+S`, `Cmd/Ctrl+Shift+S` | сохранить, сохранить как |
| `Cmd/Ctrl+E` | править / читать |
| `Cmd/Ctrl+W` | закрыть вкладку |
| `Cmd/Ctrl+B` | боковая панель |

## Где лежат данные

Electron по умолчанию хранит данные в профиле пользователя. folio переносит их
все — настройки, кэши, данные сеанса, журналы — в `folio-data/` рядом с
программой:

| Как запущен | `folio-data/` |
|---|---|
| Windows | рядом с `folio.exe` |
| macOS | рядом с `folio.app` |
| Linux | рядом с файлом `.AppImage` |
| задан `FOLIO_DATA` | этот каталог |
| из исходников | `.folio-data/` в рабочем каталоге |

Поэтому удаление папки программы удаляет всё, что она когда-либо записала.
Обратная сторона: в папку должна быть возможна запись — не распаковывайте folio
туда, куда пишет только администратор.

## Одно окно

Повторный запуск выводит работающий folio на передний план, а не запускает
вторую копию; документы открываются вкладками этого окна.
