# Как устроено

## Два вида процессов

folio — приложение на Electron, и Electron делит его на две части:

- **Главный процесс** владеет окнами, меню, диском и правилами сети. Только он
  читает и пишет файлы.
- **Окно документа** рисует документ. Оно работает с изоляцией контекста и
  песочницей Chromium, без Node.js, под политикой безопасности содержимого,
  которая разрешает только скрипты самого folio. Что оно может попросить у
  главного процесса, проходит через маленький мост (скрипт preload) — открыть,
  сохранить, прочитать файл проекта — и больше ничего.

## Что может документ


Markdown-файл может прийти откуда угодно, поэтому окно ему не доверяет:

- он видит файлы папки, из которой открыт, — их отдаёт своя схема folio, — и
  ничего за пределами этой папки;
- в сеть — «Попробовать» в справочнике API, картинка или видео по адресу — он
  ходит только после того, как вы разрешили это для файла или папки;
- он не может увести окно на другую страницу или открыть новые окна; ссылка
  открывается в системном браузере.

## Окно

Середина отдана странице; элементы управления — по краям.

- **Слева — рабочее пространство.** «Общие» и проекты, у каждого дерево
  документов. Вверху: открыть файл, новая быстрая заметка, свернуть. У каждого
  раздела своё меню: «Общие» — их папка; «Проекты» — **+** добавляет папку или
  клонирует репозиторий, **⋯** показывает скрытые проекты. Ветка репозитория —
  метка рядом с именем. **Свёрнутая** (`Cmd/Ctrl+B`) панель — узкая лента:
  «Общие» и каждый проект своими инициалами; щелчок выдвигает его дерево поверх
  страницы, пока не открыт документ.
- **Сверху — вкладки**, и только они.
- **Тулбар редактора плавает над страницей** и остаётся под рукой, как бы
  далеко вниз ни ушёл текст; у самой страницы нет рамки. В режиме **Markdown** текст занимает всё
  рабочее пространство от края до края; **рядом со страницей** — две половины
  встык через линию, каждая прокручивается сама.
- **Справа — лента.** Одна кнопка показывает, как показан документ, и по
  щелчку переключает режимы по кругу — **Чтение**, **Править визуально**,
  **Markdown**, **Markdown рядом со страницей** (у схемы — чтение и правка, у
  draw.io — чтение); правый щелчок — список, чтобы выбрать сразу. Затем история, печать и PDF; внизу — настройки
  (тема: как в системе, светлая, тёмная).

## Как открыть документ

Markdown-файл открывается через **Файл → Открыть**, перетаскиванием на окно, из
командной строки (`folio notes.md`) или — если folio уже запущен — повторным
запуском с файлом: его откроет работающий folio. Ссылка на другой документ той
же папки открывает его во вкладке. Открытые документы и активный возвращаются
после перезапуска.

### Файлы схем и описаний API

Не только Markdown: схема или описание API открывается в своей вкладке и
рисуется своим элементом embed; ссылки на такие файлы в документе тоже их
открывают.

| Файл | Рисует | Правится в |
|---|---|---|
| `.bpmn`, `.dmn` | `<dsk-bpmn>`, `<dsk-dmn>` | их редакторах: палитра, контекстное меню, свойства, отмена |
| `.drawio`, `.dio`, `.drawio.svg` | `<dsk-drawio>`, вкладки страниц | — (только просмотр) |
| OpenAPI / Swagger (`.yaml`, `.yml`, `.json`) | `<dsk-openapi>`, справочник | его визуальном редакторе с исходником и превью |
| AsyncAPI (`.yaml`, `.yml`, `.json`) | `<dsk-asyncapi>` | исходник рядом с живым превью |
| `.mmd`, `.puml`, `.dot`, `.gv`, `.d2`, `.dbml`, `.dsl`, `.wardley` | `<dsk-diagram>`, синтаксис по расширению | исходник рядом с живым превью |
| код, данные, логи, конфигурация — любой текстовый файл известного языка (17 языков программирования, JSON, XML, логи, TOML, INI, `.env`, CSV, diff, Dockerfile, Makefile, …) | пронумерованные строки в цветах его языка (`@dskripchenko/syntax`; язык — по имени, расширению или строке `#!`); файл данных (JSON, YAML, XML, TOML, CSV, INI, `.env`) проверяется — ошибки отмечены у своих строк, счётчик в шапке переходит по ним; блоки сворачиваются стрелками у номеров; большой файл (больше 2 МБ или 20 000 строк, до 200 МБ) рисует только видимые строки, а свыше 64 МБ только читается; лог фильтруется по уровню (трассировка остаётся при своей записи) и, если читать его с конца, следует за дописываемым | редактор кода |
| другой текст | как текст | редактор кода |

**Редактор кода** (`@dskripchenko/code-editor`) правит любой текстовый файл,
нотацию диаграммы и AsyncAPI рядом с их превью: подсветка при наборе,
сворачивание стрелками у номеров, проверка файла данных по мере правки.
Клавиши — как в VS Code: скобки и кавычки закрываются сами, `Cmd/Ctrl+/`
комментирует строки, `Alt+↑/↓` переносит их, `Cmd/Ctrl+D` добавляет к курсорам
следующее вхождение, `Ctrl+Space` дополняет словами файла. Отступ берётся из
`.editorconfig` проекта, иначе — из самого файла; строка состояния показывает
строку и колонку, отступ, переводы строк (LF или CRLF, как были) и язык.
Правятся файлы до 64 МБ; больший только читается.

YAML и JSON узнаются по ключу верхнего уровня `openapi`, `swagger` или
`asyncapi`; в дереве — YAML-файлы и JSON с именем как у описания API
(`openapi.json`), а не каждый `package.json`. API без сервера в сети
открывается без «Попробовать», а примеры запросов в нём — на
`http://localhost`. Сохранение, несохранённые правки, переживающие
перезапуск, история и сравнения работают для этих файлов так же, как для
Markdown.

## Общие и проекты

Рабочее пространство из двух частей: **Общие** — одна папка для документов,
общих для всего (по умолчанию `folio-data/library` или папка на ваш выбор), и
**проекты** — любые папки на диске, добавленные в folio. Список лежит в
`folio-data/workspace.json`; сами папки остаются, где были. Документ проекта или
«Общих» может читать файлы всей этой папки; отдельно открытый файл — своей папки.

Боковая панель показывает «Общие» и проекты: сначала закреплённые, потом по
группам, потом остальные; меню проекта (правая кнопка) закрепляет его,
переименовывает, кладёт в группу, скрывает или убирает из folio (папка на
диске остаётся). Деревья показывают папки и файлы, которые folio открывает,
папки первыми, и следят за диском: файл, добавленный, изменённый или удалённый
в другом месте, виден сразу, а открытый документ перерисовывается.
`Cmd/Ctrl+B` прячет панель.

В редакторе кода **символы** файла — функции, классы, методы, типы,
константы; ключи и секции конфигов — читаются по мере набора: **Оглавление**
(правая рейка) перечисляет их и отмечает тот, где стоит курсор, щелчок
переходит к нему; хлебные крошки над текстом показывают проект и папки файла,
затем символы, в которых курсор; `Cmd/Ctrl+Shift+O` переходит к символу файла по
имени, а `Cmd/Ctrl+Alt+O` — к символу любого видимого проекта (его файл
открывается в редакторе на нём). Автодополнение предлагает имена проектов
вдобавок к словам самого файла.

**Задачи** (`Cmd/Ctrl+Shift+B` или *Запустить задачу* среди команд) — свои у
проекта: скрипты `package.json` (через менеджер пакетов, названный файлом
блокировки) и `composer.json`, цели `Makefile`, рецепты `justfile` и задачи из
`.folio/settings.json`; недавние — первыми. Задача идёт в своей вкладке консоли
с её именем и заканчивается вместе с ней. Её вывод разбирается на **проблемы** —
`путь:строка:колонка: сообщение` (gcc, clang, go, ruff, mypy, pytest, unix-форма
eslint), tsc, блоки eslint stylish, rustc, psalm — и они видны в панели
**Проблемы** (правая рейка, открывается сама, если задача их нашла): каждая
ведёт к своему месту и подчёркнута в редакторе кода.

Проект кода может **форматировать при сохранении** своим инструментом —
prettier (свой у проекта), pint, gofmt, ruff, rustfmt, black или своей
командой, читающей текст со stdin, — если так сказано в
`.folio/settings.json`; меняется только то, что изменил инструмент, и
отменяется одним шагом.

`.folio/settings.json` в корне проекта — его собственные настройки, вручную (и
в репозитории, если так решат его люди):

```json
{
  "kind": "code",
  "indentUnit": "  ",
  "tabSize": 2,
  "formatOnSave": true,
  "formatter": "prettier",
  "tasks": [{ "name": "serve", "command": "php artisan serve" }],
  "lsp": { "php": ["phpactor", "language-server"], "python": false }
}
```

Вид берётся вместо угаданного, отступы — поверх `.editorconfig`. Свои клавиши —
в `folio-data/keybindings.json`, без окна для них: `[{ "key": "Mod-Shift-d",
"command": "copyLineDown" }, { "key": "Mod-Alt-p", "command": "folio.problems" }]`
— команды редактора кода по именам, команды folio как `folio.` и id команды; в
редакторе его клавиши главнее сочетаний folio.

**Языковые серверы** (LSP) понимают код в редакторе, если сервер стоит в
системе: `typescript-language-server`, `intelephense` или `phpactor`, `pyright`
или `pylsp`, `gopls`, `rust-analyzer`, `clangd` — в folio они не входят. Файл
языка запускает его сервер для проекта (он останавливается через несколько
минут после закрытия последнего файла); сервер самого проекта
(`node_modules/.bin`, `vendor/bin`, `.venv/bin`) запускается, только когда
проекту доверяют — вопрос задаётся один раз. Дальше ошибки подчёркиваются по
мере набора и попадают в **Проблемы**; указатель на имени показывает, что это;
`F12` или `Cmd/Ctrl`+щелчок — переход к определению, `Shift+F12` — ссылки,
`F2` — переименование по всему проекту (открытые файлы меняются во вкладках,
по одной отмене на вкладку), `Cmd/Ctrl+.` — исправления сервера; в дополнении
первыми идут варианты сервера, параметры вызова видны после `(`
(`Cmd/Ctrl+Shift+Space`), оглавление и крошки строятся по серверу. Строка
состояния называет сервер или что поставить; *Вывод языкового сервера* среди
команд показывает его журнал. `"lsp"` в `.folio/settings.json` задаёт языку
свою команду или `false` — без сервера; `"formatter": "lsp"` форматирует при
сохранении сервером.

**Картинки, видео и звук** открываются в своей вкладке: PNG, JPEG, GIF, WebP,
AVIF, BMP и значки вписаны в окно (маленькие — в исходном размере), масштаб —
`Cmd/Ctrl` с колесом или щипком относительно указателя, `+`, `−`, `0`
(вписать) и `1` (исходный размер), двойной щелчок переключает между ними,
большая картинка перетаскивается, прозрачность — на шахматке; MP4, WebM, MOV и
MKV — в видеоплеере, MP3, WAV, OGG, Opus, M4A, AAC и FLAC — в плеере звука с
волной. Строка состояния показывает размеры, длительность и вес; панель под
файлом открывает его в системной программе — её же предлагает файл, который
Chromium не декодирует. SVG рисуется, а правится как текст рядом с картинкой,
которая следует за набором. Медиа видны и в деревьях заметок, но как текст не
читаются: поиск, PDF папки и версии истории их пропускают.

Проект — **заметок** или **кода**: вид угадывается при добавлении (в корне
`package.json`, `composer.json`, `go.mod`, `Cargo.toml`… или git-репозиторий без
заметок кроме README — значит, код) и меняется в его меню. Проект кода
показывает все файлы, в том числе с точкой (`.github`, `.editorconfig`), а
нетекстовый файл (кроме картинок, видео и звука — их показывает сам folio)
открывается программой системы; сохранение там само не
коммитится — коммиты делаются вручную. В папке под git то, что исключает
`.gitignore` (вместе с `.git/info/exclude` и глобальным файлом исключений
пользователя), не попадает в дерево, переход к файлу и поиск, а дерево следует
за `.gitignore` по мере правки; папка без git держится своего списка служебных
папок folio (`node_modules`, `vendor`, `dist`…).

### Файлы и папки

Дерево умеет создавать и менять файлы: **Новая заметка** и **Новая папка** в
меню правого щелчка по папке или проекту (и в меню **…** у «Общих») — имя
вводится на месте, заметка сразу открывается с заголовком из имени;
**Переименовать…** (или `F2`) правит имя в строке, расширение сохраняется;
файл или папка, перетащенные на папку (или проект), переезжают туда;
**Дублировать** делает копию рядом; **Удалить в корзину** (или `Delete`,
`Cmd+Backspace`) спрашивает и кладёт в системную корзину, откуда можно вернуть.
Открытые документы следуют за переименованием и переносом; удалённый документ
закрывается, если в нём нет несохранённых правок. Имя с `/ \ : * ? " < > |` или
уже занятое отклоняется на месте, с причиной.

У файла кода рядом с именем виден его тип: буква-две в цвете стека — `JS`
жёлтым, `TS` синим, `<?` фиолетовым для PHP, `B` для Blade, `{}` для JSON и
так далее; `package.json`, `composer.json`, lock-файлы, `Dockerfile` и `.env`
узнаются по имени. Те же значки — в **Изменениях** и в ревью.

### Два документа рядом

**Открыть рядом** в меню вкладки (или `Cmd/Ctrl+\`, или команда) показывает
документ во втором виде справа; основной вид остаётся за другой вкладкой. У
каждого вида свой документ и своя прокрутка; щелчок в виде делает его документ
текущим, и за ним следуют панели, поиск и история. Разделитель между видами
перетаскивается, доля запоминается. **Вернуть в основной вид** (или снова
`Cmd/Ctrl+\`) закрывает боковой вид, документ остаётся открытым во вкладке;
закрытие его вкладки тоже закрывает вид. Печать печатает только текущий документ.

### Ссылки между заметками

`[[Заметка]]` ссылается на заметку по имени, где бы она ни лежала в том же
проекте (или в Общих): сначала папка самой заметки, затем самый короткий путь.
`[[Заметка#Раздел]]` открывает её на этом разделе, `[[Заметка|текст]]` показывает
другой текст, `![[картинка.png]]` — картинку. Ссылка на несуществующую заметку
бледнее остальных; щелчок создаёт заметку рядом со ссылающейся и открывает её. В
редакторе ссылка открывается по `Cmd/Ctrl`+щелчок, а набор `[[` подсказывает
заметки проекта. Заметка или папка, переименованная или перенесённая в дереве,
уносит ссылки с собой: ссылки `[[…]]` и относительные (`[текст](notes/plan.md)`,
картинки) в заметках проекта переписываются, как и относительные ссылки самой
перенесённой заметки; заметки, открытые с несохранёнными правками, не трогаются.

**Панель «Ссылки»** (значок ссылки на правой ленте) показывает для заметки на
экране заметки, которые на неё ссылаются, её собственные ссылки —
несуществующие бледнее, щелчок создаёт заметку — и заметки, где она названа без
ссылки; **Связать** превращает такое упоминание в `[[Заметка]]` (написание
сохраняется текстом ссылки). Щелчок по строке открывает заметку на ней. Панель
следует за заметкой на экране и за набором.

### Заметки дня и шаблоны

`Cmd/Ctrl+Shift+D` (или **Заметка дня** в командах) открывает заметку дня —
`ГГГГ-ММ-ДД.md` в папке заметок дня (`Daily` в «Общих», если не выбрана
другая), — создавая её при необходимости из шаблона `Daily`, если он есть.
**Предыдущая / следующая заметка дня** ведёт к ближайшей существующей. Шаблон —
заметка в папке шаблонов (`Templates` в «Общих»): **Вставить шаблон…** ставит
его в позицию курсора, **Новая заметка из шаблона…** делает из него быструю
заметку; `{{title}}`, `{{date}}`, `{{time}}` и `{{date:DD.MM.YYYY}}`
подставляются. Обе папки выбираются в меню настроек.

`![[Заметка]]` встраивает другую заметку в эту — нарисованной как при чтении, в
рамке с её ссылкой; `![[Заметка#Раздел]]` встраивает раздел. Встраивание внутри
встраивания тоже рисуется (до трёх уровней), заметка, встраивающая саму себя,
остаётся ссылкой, а в редакторе встраивание — это его ссылка, сохраняемая как
написано.

Другие имена заметки — `aliases:` в её свойствах (`aliases: [Дорожная карта]`) —
работают в ссылках как её имя: `[[Дорожная карта]]` находит её, если файла с
таким именем нет, а `[[` предлагает их, записывая `[[Roadmap|Дорожная карта]]`.

### Оглавление

Панель оглавления (на правой ленте или в командах) показывает заголовки
заметки на экране с отступами по уровню, по мере набора; щелчок ведёт к
заголовку — в исходнике ставит курсор на его строку, — а раздел на экране
отмечается при прокрутке.

### Орфография и строка состояния

Орфография проверяется по мере набора — системой на macOS и Windows, без сети;
в Linux Chromium скачивает словари, поэтому там проверка выключена, пока её не
включить в меню настроек. Меню поля предлагает исправления, **Добавить в
словарь**, вырезать, копировать и вставить. Под страницей строка состояния
показывает число слов, знаков и минут чтения документа, а в исходнике Markdown —
строку и столбец курсора.

### Граф

Панель графа (на правой ленте или в командах) рисует заметки проекта на экране
точками, а ссылки между ними — линиями: **Эта заметка** — заметки не дальше двух
ссылок от текущей, **Все** — весь проект. Размер точки — число её связей,
текущая заметка выделена цветом; курсор на точке подсвечивает её и соседей,
щелчок открывает заметку; колесо масштабирует, перетаскивание двигает
картинку.

### Закладки

Файл под рукой: **В закладки** в меню вкладки, в меню файла в дереве или в
командах. Закладки перечислены над «Общими»; щелчок открывает файл, меню
убирает закладку. Закладка следует за файлом, переименованным или перенесённым
в folio; закладка на файл, исчезнувший в другом месте, остаётся бледной.

### Доски и календари

Файл `*.kanban.md` открывается канбан-доской, `*.calendar.md` — календарём;
оба записаны разметкой, которую прочтёт любой редактор (колонки `## …` и
карточки `- …`; события `2026-11-03 10:00 …`, повторы `every mon …`). **Править**
делает их редактируемыми прямо на себе: карточки перетаскиваются и
добавляются, события двигаются, исходник — на своей вкладке; файл хранит
разметку, меняясь только там, где была правка. **Новая канбан-доска** и **Новый
календарь** в командах создают их рядом с заметкой на экране.

### Холсты

Файл `*.board` открывается как доска-холст (`@dskripchenko/board`): стикеры,
фигуры, текст, рамки, связи, эмодзи, перо и маркер на бесконечном поле.
**Править** — рисовать на ней; файл хранит JSON доски с отступами, так что
разница версий показывает, что сдвинулось. **Новый холст** среди команд
создаёт его рядом с открытой заметкой.

### Задачи

Панель задач (на правой ленте или в командах) перечисляет задачи `- [ ]`
проекта на экране по сроку — **Просрочено**, **Сегодня**, **Позже**, **Без
даты**, — а с **Все** и сделанные; срок пишется `📅 2026-11-10`, `@2026-11-10`
или `due:2026-11-10`. Задача отмечается или снимается прямо из панели, в её
заметке (кроме открытой с несохранёнными правками); щелчок по тексту открывает
заметку на ней.

### Слайды

**Показать слайдами** (`F5` или среди команд) показывает заметку на весь экран,
по слайду: слайды — её части между строками `---`, перед которыми пустая
строка (вне кода и свойств, как в Marp и reveal.js). Стрелки, пробел,
Page Up/Down, Home и End или щелчок по левой или правой половине листают их;
Escape завершает показ. **Экспорт слайдов в PDF** (среди команд или на панели
показа) пишет по странице 16:9 на слайд.

### Предпросмотр

Курсор, задержавшийся на `[[ссылке]]` или ссылке на заметку, показывает
заметку в окне у ссылки — нарисованной как при чтении, на разделе, который
называет ссылка. Окно прокручивается; щелчок в нём открывает заметку; уход
курсора или Escape закрывает его. В редакторе предпросмотр ждёт `Cmd/Ctrl`.

### Теги и свойства

`#todo`, `#work/urgent` в заметке — теги (нужна хотя бы одна буква: `#123` — не
тег, `C#` — тоже); `tags:` в её свойствах — тоже теги. Свойства заметки — YAML
front matter в её начале, строки `---` вокруг `ключ: значение` — показываются
таблицей над ней и в редакторе хранятся ровно как написаны. Панель тегов
(значок тега на правой ленте или команда) показывает теги проекта на экране с
числом заметок, вложенные — под родителями; раскрытый тег показывает свои
заметки, щелчок открывает заметку; фильтр находит тег по имени. Щелчок по тегу
в заметке открывает панель на нём (в редакторе — с `Cmd/Ctrl`).

### Формулы и выделение

Формулы TeX рисуются так, как читаются: `$E = mc^2$` в строке, `$$ … $$` (или
блок ` ```math `) отдельными строками — собственным пакетом folio
`@dskripchenko/math`, как MathML. Цена (`$5 или $10`) остаётся текстом. В
визуальном редакторе формула — единый кусок: двойной щелчок правит её TeX,
**Формула** в меню `/` добавляет новую, а файл хранит её ровно как написано;
в исходнике Markdown её TeX подсвечивается. Скобки и корни растягиваются в
математическом шрифте: системном (macOS, Windows) или STIX Two Math, который
folio везёт с собой (SIL Open Font License). `==текст==` выделяется.

### Картинки

Картинка, вставленная в заметку (снимок экрана, скопированное изображение) или
перетащенная на редактор — в визуальном режиме или в исходнике, — сохраняется в
`attachments/` рядом с заметкой и вставляется ссылкой в позицию курсора: под
своим именем, а снимок без имени — как `Pasted image` и время; занятое имя
получает номер. Кнопка картинки на панели редактора так же берёт картинки с
диска. Быстрая заметка, ещё не сохранённая, просит сначала сохранить её —
картинкам нужна папка.

## История в git

Для каждой папки отдельно — «Общих» и каждого проекта — и только по желанию.
Папка-репозиторий git (или папка внутри него) показывает историю сразу; другая
заводит её кнопкой **Вести историю** на панели **История** (`Cmd/Ctrl+Shift+H`):
репозиторий на ветке `main` и первый коммит того, что в папке есть.

- **Фиксировать при сохранении** — включено для истории, заведённой folio, и
  выключено для уже существующего репозитория (folio не коммитит в чужой
  проект сам). Сохранённый файл фиксируется через 3 минуты после последнего
  сохранения, так что серия сохранений даёт один коммит; при выходе из folio
  ожидающее фиксируется сразу. Фиксируется только сохранённый файл, с
  сообщением *Update <путь>*; **Зафиксировать** со своим сообщением делает это
  сразу.
- **Версии** открытого файла, новые сверху. Версия открывается только для
  чтения, как была; **Изменения** показывают разницу с текущей построчно,
  **Рядом** — два отрисованных документа, со схемами. **Вернуть эту версию**
  кладёт её текст в редактор как несохранённую правку — сохранять или нет,
  решаете вы.
- **В дереве**: изменённые файлы помечены, папка с изменениями внутри — точкой,
  у проекта видна ветка.
- Автор — `user.name` / `user.email` из конфигурации репозитория, затем из
  `~/.gitconfig`, иначе пользователь системы.

git встроен в folio (isomorphic-git, чистый JavaScript), поэтому всё это
работает там, где git не установлен. Кое-что требует git, установленного в
системе, и говорит об этом, если его нет: ревью изменений и worktree (ниже),
отложить изменения и отменить коммит, а также worktree, открытый как проект, —
isomorphic-git его не читает, поэтому изменения, история и метки на полях там
идут через системный git.

### Изменения

`Ctrl+Shift+G` на всех системах (или кнопка коммита на правой рейке) открывает
панель **Изменения**, как контроль версий редактора кода: файлы, изменённые в
рабочей папке, и добавленные в индекс для следующего коммита, у каждого буква
(**A** — добавлен, **M** — изменён, **D** — удалён, **U** — не отслеживается).
Файл добавляется в индекс и убирается из него кнопками `+` и `−` (или все сразу
из заголовка группы), изменения отменяются стрелкой — с вопросом, вернуть их
нельзя, — а щелчок по имени открывает файл. Сообщение и **Коммит** (или
`Cmd/Ctrl+Enter`) коммитят индекс. Панель следует за документом на экране и
смотрит заново при изменениях на диске. В проекте кода коммиты делаются так:
сохранение там само не коммитится.

### Изменения на полях, кто менял строку

Файл под git в редакторе кода отмечает свои изменения относительно последнего
коммита у номеров строк по мере набора: зелёная полоса — добавленные строки,
синяя — изменённые, красная засечка — место удалённых. Щелчок по метке
показывает, какими строки были, и кнопку **Вернуть**, чтобы отменить это
изменение. Команда **Кто менял каждую строку (blame)** добавляет колонку у
номеров — автор и давность, а при наведении сообщение коммита, автор и дата;
та же команда убирает её. Используется системный git, если он есть, иначе
история файла читается самим folio.

### Ревью работы агента

folio рассчитан на работу рядом с ИИ-агентом в терминале: в основном вы
читаете и ревьюите то, что он поменял, и немного правите.

- **Ревью** (кнопка-страница в **Изменениях**, команды или меню коммита в
  истории) открывает изменения как файлы пулл-реквеста, во вкладке: файлы
  слева, изменения каждого справа с тремя строками контекста, неизменённое
  свёрнуто, в одну колонку или в две, в цветах языка, изменённые внутри строки
  слова подсвечены. Рабочая копия, коммит, изменения после коммита, worktree
  относительно базы — всё в одном виде. Файл с отметкой **Просмотрено**
  сворачивается и остаётся отмеченным, пока его текст не изменится. В рабочей
  копии каждый фрагмент из своего заголовка отправляется в индекс, убирается
  из него или откатывается. Двойной щелчок по строке (или **Править**)
  открывает файл рядом с ревью на этой строке для правки. Ревью следит за
  диском: написанное агентом появляется само, изменившийся файл на мгновение
  подсвечивается. Список файлов — плоский или деревом папок (кнопка над ним,
  выбор запоминается): сначала папки, папка с единственной папкой внутри
  показана с ней одной строкой (`src/http/controllers`), папка сворачивается
  щелчком.
- **С последнего просмотра** показывает только то, что изменилось с прошлого
  просмотра, — правки и коммиты самого агента, свежие сверху, со временем.
  **Просмотрено** на файле сдвигает точку просмотра для него, **Всё
  просмотрено** — для всех. **Изменения** показывают число таких файлов.
- **Worktree** (кнопка-ветка на правой рейке) перечисляет worktree
  репозитория — агента или субагента, в `.claude/worktrees` или где угодно — с
  веткой, коммитами впереди и позади базы, изменёнными файлами и временем.
  Каждый можно отревьюить относительно базы, открыть как проект (там работают
  его изменения, история и метки на полях) или в терминале, забрать его
  изменения в основную копию без коммита, влить или удалить вместе с веткой.
  Worktree внутри проекта не попадают в поиск и переход к файлу.
- **Замечания**: `+` у номера строки добавляет замечание; оно держится своей
  строки, когда строки сдвигаются. **Отправить агенту** вставляет
  неотправленные замечания — каждое с файлом, строкой и строками вокруг — в
  консоль, где работает агент, одной вставкой и без Enter: прочитайте там и
  отправьте сами.
- **Подключить Claude Code к folio** (команды) добавляет хук в
  `.claude/settings.local.json` репозитория (показывается до записи): после
  каждой правки Claude Code сообщает folio файл, сессию и время, и ревью и
  worktree подписывают, кто что поменял. Ещё она добавляет в Claude Code для
  этого проекта MCP-сервер folio — собственной командой Claude Code
  `claude mcp add --scope local` (его настройки, не репозиторий; команда тоже
  показывается, а если не выполнилась, folio скажет, что запустить). У агента
  появляются четыре инструмента: `show_changes` открывает ревью с его
  сообщением и ждёт ответа — **Принять** или **Вернуть с замечаниями** к
  строкам, каждое с файлом, строкой и соседними строками;
  `get_review_comments` читает ещё не отданные замечания; `open_file` открывает
  файл на строке; `list_worktrees` перечисляет worktree. Пока folio закрыт,
  агенту говорится запустить его. **Отключить** убирает хук и сервер и ничего
  больше.

Для ревью нужен git, установленный в системе.

### Ветки и синхронизация

- **Ветки**: имя ветки в панели открывает список — перейти на другую или
  создать новую от текущего места. Переход не выполняется, пока в файлах есть
  изменения, которые он перезаписал бы (ждущие паузы коммиты делаются сначала).
- **Удалённый репозиторий**: папке без него адрес задаётся в панели;
  репозиторий, клонированный в folio (**Файл → Клонировать репозиторий…** или ⤓
  рядом с «Проектами»), приходит со своим и становится проектом с включённым
  «Фиксировать при сохранении».
- **Синхронизировать** — получить, принять коммиты удалённого репозитория
  (перемотка вперёд или коммит слияния, если двигались обе стороны) и отправить
  свои; на кнопке видно, сколько уходит и приходит (↑ ↓). Все изменения должны
  быть зафиксированы.
- **Конфликт** остаётся в тексте, как его оставляет git: обе версии между
  строками `<<<<<<<` и `>>>>>>>`, файлы перечислены в панели. Поправьте их (в
  folio или где угодно), сохраните и нажмите **Завершить слияние** — пока
  остаётся маркер, слияние не завершится; **Отменить слияние** возвращает вашу
  версию. Слияние хранится так же, как у git (`MERGE_HEAD`), — системный git его
  тоже видит, — и до завершения сохранение не создаёт коммитов.
- **Сеть**: через системный git, если он установлен, — его помощники учётных
  данных и SSH-ключи работают как в терминале (пароль в невидимом терминале он
  не спрашивает). Без него folio сам говорит по HTTPS: когда удалённый
  репозиторий просит войти, панель принимает пользователя и токен; они хранятся
  зашифрованными средствами системы (Keychain, DPAPI, Secret Service) в
  `folio-data/logins.json` — или только до конца сеанса, если шифрования в
  системе нет. Синхронизация — ваше действие, согласия на сеть, как у
  документов, она не требует.

### Граф коммитов

Рядом со списком — граф как в Fork: по полосе на линию разработки, слияния —
кольца, соединяющие полосы, ветки идут рядом с основой и возвращаются в неё.
**Этот файл** — версии файла, линии проходят сквозь коммиты, которые файл не
трогали (как упрощает историю `git log -- file`); **Все коммиты** — весь
репозиторий: его ветки, ветки удалённого репозитория на момент последнего
получения и теги — с подписями на коммитах, текущий отмечен. Выбор коммита
открывает файл таким, каким он был тогда. Граф рисует `@dskripchenko/diagrams`
(`renderCommitGraph`).

## Вкладки, таблицы, сравнение, экспорт, настройки

**Вкладки.** `Cmd/Ctrl+Shift+T` возвращает последнюю закрытую вкладку — на её
место в ряду, в её режиме, прокрученной туда же. Вкладку можно перетащить в
другое место ряда, на правую половину вида — открыть рядом с основной, и обратно
на левую.

Меню вкладки закрывает её, другие, те, что справа, сохранённые или все
(`Cmd/Ctrl+Shift+W`): сначала закрываются сохранённые, затем про каждую с
изменениями спрашивается, «Отмена» останавливает. У вкладки может быть свой
цвет, и она может входить в группу: перед вкладками группы стоит ярлык с
названием и цветом, сами они стоят подряд и подчёркнуты этим цветом. Щелчок по
ярлыку сворачивает группу (вкладки скрыты, видно их число); вкладка входит в
группу из своего меню или если её бросить на ярлык или между вкладками группы.
Меню ярлыка переименовывает, перекрашивает, расформировывает или закрывает
группу. Цвета и группы хранятся в сессии.
**Показать в дереве** в меню (и в палитре) находит проект файла — или «Общие»,
раскрывает его папки и показывает строку, с фокусом на ней: во всплывающем
дереве, если сайдбар свёрнут; скрытый проект показывается.

**Вставки файлов.** `![[фото.png]]`, `![[ролик.mp4]]`, `![[песня.mp3]]` и
`![[отчёт.pdf]]` показывают файл в заметке; он находится по имени в любом месте
проекта, как ссылка; `![[фото.png|300]]` или `|300x200` задают размер. Щелчок
по картинке открывает её во вкладке, наведение на ссылку показывает её.

**Длинные строки** в прозе (простой текст, Markdown, журналы) переносятся по
ширине вида, в коде — нет; `Alt+Z` (или «Переносить длинные строки» в командах)
меняет это для открытого редактора и запоминает для такого вида текста.

**PDF** открывается во вкладке во встроенном просмотрщике Chromium: страницы,
масштаб, поиск, оглавление, печать.

**CSV и TSV** показываются таблицей: разделитель угадывается, шапка остаётся на
виду, щелчок по столбцу сортирует (числа — по значению), строки по тысяче;
исходник правится в редакторе кода.

**Сравнение двух файлов**: «Выбрать для сравнения» у одного в дереве, затем
«Сравнить с…» у другого — или «Сравнить файл с…» в командах для открытого
файла. Изменения, рядом, или другой файл целиком; «Взять его текст» переносит
его в редактор.

**Экспорт.** «Экспорт в HTML» пишет одну страницу — картинки и схемы внутри,
вид как в folio; «Экспорт в Word (DOCX)» — заголовки, выделение, ссылки,
списки, цитаты, код, таблицы и картинки, схемы — картинками.

**Git сверх коммитов.** В «Изменениях»: флажок под сообщением исправляет
последний коммит (его сообщение подставляется); кнопка сохранения откладывает
все изменения, новые файлы тоже (stash, названный сообщением) — список под
изменениями возвращает их или удаляет. В истории: меню коммита отменяет его
новым коммитом (revert) или ставит тег (`v1.2.0 Текст` — аннотированный тег);
тег уходит со следующей синхронизацией. Ветки переименовываются и удаляются в
меню веток. Для stash и revert нужен установленный git.

**Настройки** (`Cmd/Ctrl+,` или меню шестерёнки): все команды folio и редактора
кода с клавишами — «Назначить» берёт нажатые клавиши (в `keybindings.json` с
`Mod`, так файл работает на любой системе), конфликт показывается; и
`.folio/settings.json` проекта формой — незнакомые folio ключи сохраняются.

## Языки и приветствие

folio сразу говорит по-английски и по-русски: на языке системы или на
выбранном в меню настроек (сразу, запоминается). Все тексты — JSON-словари
(`src/locales/<код>.json`: `meta`, `main` — меню и диалоги, `window`,
`print`); другой язык — ещё один такой файл, в репозитории или в
`folio-data/locales/<код>.json` без пересборки folio. Чего в нём нет — берётся
из английского; формы числа — список в порядке `Intl.PluralRules`
(`["{n} файл", "{n} файла", "{n} файлов"]`).

«Возможности folio» (команды, меню «Справка», пустое окно) открывает страницу
только для чтения со всеми видами блоков, нарисованными вживую; при первом
запуске она открывается сама, на языке интерфейса.

## Несохранённое и быстрые заметки

Как в Sublime Text: безымянная вкладка — быстрая заметка, а несохранённая правка
не попадает в файл. И то и другое пишется в `folio-data/session/` по ходу
набора, поэтому переживает закрытие folio, сбой и перезагрузку компьютера и
возвращается в том же виде. Вкладка с несохранёнными правками помечена точкой.
Закрытие такой вкладки спрашивает, сохранить ли; закрытие folio не спрашивает
ничего — всё уже на диске. Если файл изменился на диске, пока вы правили,
folio говорит об этом и хранит оба варианта: взять файл с диска или оставить
свою версию и сохранить её поверх. Быструю заметку **Сохранить** кладёт в
«Общие» (или куда угодно), с именем по её первой строке.

## Печать

**Файл → Печать** (`Cmd/Ctrl+P`) печатает активный документ как документ:
в режиме чтения, а не правки; боковая панель, вкладки, кнопки и история folio
на бумагу не попадают, а бумага светлая, какой бы ни был экран. Каждый виджет
печатается в своей форме для печати из embed (`DskEmbed.print.prepare`):
схема BPMN или DMN целиком (файл DMN — с таблицами решений), все страницы
draw.io, процесс или доска целиком, справочник API — своим статическим
документом, видео — постером и главами, канбан и календарь — без элементов
управления. Дальше открывается системный диалог печати; PDF сохраняется через «Экспорт в PDF» (ниже).

### PDF

**Файл → Экспорт в PDF** (`Cmd/Ctrl+Shift+P`) сохраняет активный документ —
как он показан, с несохранёнными правками, — а **Экспорт папки в PDF** (меню
проекта или папки в дереве) сохраняет всю папку одним PDF. Диалог спрашивает
один раз и запоминает:

- размер страницы (A4, A3, A5, Letter, Legal, Tabloid), книжная или
  альбомная, поля (без полей, узкие, обычные, широкие);
- название вверху каждой страницы, номера страниц (`3 / 12`) внизу;
- оглавление со ссылками перед текстом; закладки по заголовкам (структура
  PDF, в размеченном PDF);
- цвета и фоны схем.

Папка печатается в порядке книги: в каждой папке сначала `index.md` или
`README.md`, затем документы по имени, затем вложенные папки; каждый документ
с новой страницы, файлы схем и API — с именем файла заголовком. Ссылка из
одного документа на другой становится ссылкой внутри PDF. Страницы
раскладываются в скрытом окне сеанса документов — согласие на сеть действует
и там — с каждым виджетом в форме для печати, затем Chromium печатает их в PDF.

## Правка

`Cmd/Ctrl+E` (или **Править** на панели) превращает документ в редактор и
обратно. У редактора три режима: визуальный (правка как в текстовом
процессоре — панель инструментов, меню `/`, все блоки живые), сам Markdown и
оба рядом. Файл остаётся Markdown: то, что визуальный режим не держит
(заголовки ниже h3, выноски, HTML), сохраняется как написано, а картинки
сохраняют свои относительные пути. Чек-листы — списки с флажками: щелчок
отмечает пункт, `[ ] ` или `[x] ` в начале пункта делает его задачей.

| `Cmd/Ctrl+O` | открыть файл |

## Поиск

`Cmd/Ctrl+Shift+F` (**Правка → Найти в файлах** или лупа на правой ленте)
открывает панель рядом со страницей: поиск по тексту файлов — всех, «Общих» или
одного проекта — с теми же тремя настройками. Совпадения появляются по мере
нахождения, по файлам, каждая строка — с совпадением; щелчок открывает файл, и
строка поиска встаёт на это совпадение. Двоичные файлы, файлы больше 8 МБ и
папки, исключённые из перехода к файлу, не просматриваются; показывается не
больше 200 совпадений на файл и 5 000 всего.

Стрелка перед запросом открывает **Замену**: у каждого совпадения видно, во
что оно превратится, флажки отмечают файлы, которые участвуют, а **Заменить
всё** переспрашивает с числом совпадений, прежде чем писать. С регулярным
выражением `$1`, `$&` и подобные означают его группы; без него текст берётся
как есть. Файл, открытый с несохранёнными правками, пропускается (об этом
сказано), чтобы не потерять ни одну из версий; открытый без правок — показывает
новый текст. Папка с историей получает один коммит на всю замену —
`Replace "a" with "b"`, — а не коммит на каждый файл.

`Cmd/Ctrl+K` или `F1` (**Вид → Команды**) открывает палитру действий folio —
тех, что в меню и на лентах, — они ищутся так же, по названию, у каждого видны
его клавиши; недавно использованные идут первыми, а те, что сейчас выполнить
нельзя (сохранить без открытого документа, включить уже включённый режим), не
предлагаются.

`Cmd/Ctrl+T` (**Файл → Перейти к файлу**) открывает палитру всех файлов,
которые folio открывает, в «Общих» и видимых проектах; список ранжируется по
мере набора имени: символы по порядку, не обязательно подряд — `rn` находит
`release-notes.md`, первые буквы слов весят больше всего, совпадение в имени —
больше, чем в папках. Стрелки выбирают, Enter открывает, Escape закрывает.
Список собирается по папке один раз и держится, пока в ней не появится или не
исчезнет файл; папки зависимостей и сборки (`vendor`, `dist`, `build`,
`target`, `coverage`…) в него не входят, хотя дерево их показывает.

`Cmd/Ctrl+F` (**Правка → Найти**) открывает строку поиска над страницей: все
совпадения отмечены, текущее показано; Enter и Shift+Enter переходят по ним,
счётчик показывает, где вы. **Aa** — с учётом регистра, **ab** — слово целиком
(в любом алфавите), **.\*** — регулярное выражение. В чтении и визуальном
редакторе ищется страница как она нарисована — совпадение не переходит из
абзаца в абзац, а сама страница не меняется; в исходнике Markdown ищется поле,
в файле в редакторе кода — весь его текст с отметками совпадений, и по Escape текущее совпадение
остаётся выделенным в нём; большой файл ищется целиком, а не только по видимым
строкам. Если страница меняется под строкой поиска — правка, файл изменился на
диске, — поиск повторяется.

## Консоли

`` Ctrl+` `` (**Вид → Консоль** или кнопка консоли на правой ленте) открывает под
страницей панель с вашей оболочкой — zsh или bash, как её запускает терминал,
PowerShell в Windows — в «Общих»; **Открыть консоль здесь** в меню проекта или
папки открывает консоль в этой папке. Вкладки держат несколько консолей; **+**
открывает ещё одну в той же папке, × на вкладке завершает её оболочку.
Полноэкранные программы — `vim`, `htop`, `less`, `mc` — работают как в
терминале, с мышью, если они её просят; высота панели тянется за верхний край,
а тема следует за светлой или тёмной темой окна. Не на Mac Ctrl с буквой в
консоли принадлежит оболочке (^W, ^E, ^P…), а не сочетаниям folio, — кроме Ctrl+F: он ищет по выводу. Консоли
завершаются вместе с окном.

Для zsh, bash и PowerShell folio немного дополняет запуск оболочки (после ваших
собственных файлов запуска, которые выполняются как всегда): у приглашения каждой
команды появляется метка — зелёная при успехе, красная при ошибке, пульсирующая,
пока команда выполняется; при наведении — команда, код выхода и длительность;
щелчок выделяет её вывод. Вкладка показывает, что выполняется, и папку (следит за
`cd`), точку — если команда завершилась ошибкой или фоновая вкладка что-то
вывела. `Cmd+↑`/`Cmd+↓` (`Ctrl+Shift+↑`/`↓` не на Mac) — от команды к команде,
`Cmd+K` (`Ctrl+Shift+K`) — очистить, `Cmd+D` (`Ctrl+Shift+D`) — вторая консоль
рядом; `Cmd+F` в консоли ищет по её выводу. Путь в выводе — `src/app.ts:12:3` —
открывается в folio на своей строке по Cmd (Ctrl) и щелчку; файл, перетащенный из
дерева (или из системы), набирается как его путь. Колесо сдвигает вывод по строкам, не больше трёх за событие, как бы система ни
разгоняла колесо мыши или взмах по трекпаду, — длинный вывод читается по
нескольку строк. У вкладок есть цвета и группы, как у вкладок документов (меню
вкладки, меню ярлыка), и закрытие других, тех, что справа, или всех. Правый щелчок: копировать,
вставить, выделить всё, найти, очистить, разделить, панель справа или на всё
окно. `FOLIO_SHELL_INTEGRATION=0` запускает оболочки как есть. Рисует `@dskripchenko/terminal`, оболочка работает в
`node-pty`.

Замечания ревью уходят в консоль одной вставкой (см. *Ревью работы агента*):
folio вставляет только в программу, которая принимает вставку целиком, — zsh,
bash 5.1+, PowerShell, CLI агента — и никогда не нажимает Enter.

## Ресурсы, журнал, «не засыпать»

**Индикатор** внизу правой панели показывает память, которую занимает folio:
главный процесс, окно, графика, помощники Chromium, запущенные им языковые серверы.
Полоска под цифрой — до лимита памяти; на трёх четвертях лимита она жёлтая, выше —
красная. В подсказке ещё и процессор. По щелчку открывается окно **Процессы**:
каждый процесс с памятью и процессором, график за последние полчаса с линией
лимита, языковой сервер перезапускается кнопкой **Перезапустить**, консоль
закрывается кнопкой **Закрыть**. То, что работает в консолях folio — агент,
сборка, — показано отдельно, под **В консолях (не в счёт)**: это не folio, в его
сумму и лимиты не входит. Замер — раз в 15 секунд, раз в 2 — пока окно открыто.

**Лимиты** — в окне настроек, вкладка **Приложение**. Лимит памяти folio (4 ГБ по
умолчанию, 0 — без лимита) мягкий: при превышении folio сбрасывает индексы файлов и
символов и кэш Chromium и перезапускает самый тяжёлый языковой сервер; если и через
минуту больше лимита — сообщает, кто занимает больше всего, с кнопками
**Перезапустить его**, **Перезапустить folio** и **Процессы**. У языкового сервера
свой лимит (2 ГБ по умолчанию): при превышении он перезапускается со своими
файлами; серверу на Node этот лимит передаётся и как предел кучи. Жёсткий лимит
кучи процесса (по умолчанию выключен) — крайняя мера: процесс, достигший его,
падает вместе с несохранённым; применяется при следующем запуске.

**Журнал** — `folio-data/logs/folio-ГГГГ-ММ-ДД.log`, по объекту JSON в строке: запуски
и выходы, ошибки приложения и окна, упавшие и зависшие процессы, запуски языковых
серверов, срабатывания лимитов, включение и выключение «не засыпать» и раз в минуту
замер по каждому процессу — по нему потом видно, когда и что начало расти. Файлы
старше срока хранения (5 дней по умолчанию, 1–30 в настройках) удаляются, вместе с
аварийными дампами (`folio-data/crashes/`, никуда не отправляются); файл одного дня
ограничен 50 МБ и продолжается в `.1`. Текстов документов и токенов в журнале нет.
**Справка → Открыть папку журнала** и **Сохранить отчёт…** — ZIP с последними
файлами журнала, дампами и версиями для отправки. Агент читает журнал через
MCP-сервер folio, инструмент `get_app_log`.

**Не засыпать** — чашка в правой панели или палитра команд: пока не выключу, на 1, 2
или 4 часа, или **пока в консоли идёт команда** и минуту после (по меткам shell
integration: работающий агент держит компьютер, приглашение командной строки
отпускает); экран при этом тоже не гаснет и заставка не включается, если не отмечено **Разрешить экрану гаснуть** (запоминается). Работает на macOS,
Windows и Linux (на Linux — через запрет сна окружения рабочего стола: GNOME и KDE
его принимают, голый оконный менеджер может нет — тогда подсказка чашки говорит, что
система запрос не приняла). Mac с закрытой крышкой без внешнего монитора и питания
всё равно уснёт: это folio не обходит.

### Под нагрузкой агента, после сбоя, состояние машины

**За изменениями на диске folio следит бережно.** То, что пересчитывается на каждое
изменение — git-метки дерева, файлы для ссылок, тегов, графа и задач, — идёт не
больше одного раза одновременно на репозиторий или папку; кто спросил в это время,
получает следующий пересчёт, а список файлов папки хранится, пока в ней ничего не
изменилось. Изменения внутри результатов сборки и кэшей инструментов не
отслеживаются вовсе: `dist`, `build`, `out`, `target`, `vendor`, `coverage`, `.next`,
`.nuxt`, `.turbo`, `.cache`, `__pycache__`, `.venv`, `venv`, `.gradle` — агент при
сборке и тестах пишет туда тысячи файлов. Сама папка в дереве появляется и исчезает,
её файлы видны при раскрытии. Свой список проект задаёт в `.folio/settings.json`, и он
заменяет список по умолчанию: `"watchExclude": ["generated", "src/gen"]` (имена — где
угодно, пути — от корня).

**Журнал говорит, что было медленно**: запрос окна дольше 2 секунд (его имя и время —
без путей и текстов), остановка главного процесса на секунду и больше, а в минутном
замере — задержка цикла событий и очереди работы. В окне **Процессы** видна и задержка
главного процесса.

**После сбоя** — прошлый запуск начался и не завершился: его остановила система или он
упал — folio при следующем запуске один раз сообщает об этом с кнопками **Открыть
папку журнала** и **Сохранить отчёт…**.

**Диск**, на котором лежит `folio-data`, проверяется при запуске и раз в десять минут:
если свободно меньше 5 ГБ (вкладка **Приложение** в настройках; 0 — никогда), folio
сообщает с кнопкой **Очистить кэши**. Там же видно, сколько занимает `folio-data` и
чем — кэш Chromium, обновления, аварийные дампы, журнал, несохранённое; **Очистить
кэши** удаляет кэш Chromium, скачанные обновления (готовое к установке остаётся) и
дампы. Несохранённое, отметки ревью и настройки не трогаются никогда. **От батареи**
folio замеряет ресурсы раз в минуту вместо раза в 15 секунд.

### Уведомления из консолей

Когда folio не на переднем плане, системное уведомление сообщает:

- команда в консоли, шедшая дольше минуты (**Приложение**: секунды; 0 — никогда),
  закончилась — команда, её время, с ошибкой ли;
- программа в консоли просит внимания: сообщение через OSC 9 или OSC 777 либо звонок,
  пока идёт команда (не чаще раза в 30 секунд на консоль). Claude Code шлёт их, когда
  закончил или ждёт ответа, если задан канал: `"preferredNotifChannel": "iterm2"`
  (сообщение) или `"terminal_bell"` (звонок) в `~/.claude/settings.json` либо
  **Local notifications** в его `/config`. Значение по умолчанию, `auto`, в
  консолях folio ничего не шлёт.

Щелчок по уведомлению выводит folio вперёд на этой консоли. В подсказке вкладки
консоли — память и процессор её программ; вкладка, чьи программы занимают больше
гигабайта, показывает это. Больше 8 ГБ (**Приложение**; 0 — никогда) или процессор
занят пять минут подряд — folio сообщает с кнопками **Процессы** и **Закрыть консоль**
и сам ничего не делает: это не его программы.

## Где лежат данные

Electron по умолчанию хранит данные в профиле пользователя. folio переносит их
все — настройки, кэши, данные сеанса, журналы — в `folio-data/` рядом с
программой:

| Как запущен | `folio-data/` |
|---|---|
| Windows | рядом с `folio.exe` |
| macOS | рядом с `folio.app` |
| Linux | рядом с файлом `.AppImage` |
| задан `FOLIO_DATA` | этот каталог |
| из исходников | `.folio-data/` в рабочем каталоге |

Поэтому удаление папки программы удаляет всё, что она когда-либо записала.
Обратная сторона: в папку должна быть возможна запись — не распаковывайте folio
туда, куда пишет только администратор.

На macOS скачанный `folio.app`, запущенный там, где его распаковали, работает
из копии только для чтения (App Translocation): рядом с ней ничего не записать.
Тогда folio предлагает переместить себя в «Программы» и запускается оттуда;
или перетащите `folio.app` в любую папку в Finder до первого запуска.

Внутри: рабочее пространство и настройки (`workspace.json`), свои сочетания
клавиш (`keybindings.json`), разрешения сети (`consent.json`), входы для
синхронизации в зашифрованном виде (`logins.json`), «Общие» (`library/`),
открытые вкладки и несохранённые правки (`session/`), отметки ревью —
просмотренные файлы, замечания, точки последнего просмотра и правки, о которых
сообщил Claude Code (`review/`), — свои языки (`locales/`), обновления
(`update/`), журналы и данные самого Chromium (`chromium/`).

В ваши папки пишется два файла, и только по просьбе: настройки проекта из окна
настроек — в его `.folio/settings.json`, а **Подключить Claude Code к folio**
добавляет хук в `.claude/settings.local.json` репозитория (локальный файл, не в
коммите) и MCP-сервер folio в локальные настройки Claude Code для проекта —
**Отключить Claude Code** убирает оба. Удаление folio их не трогает. MCP-сервер
folio слушает только 127.0.0.1 и отвечает только с токеном, который лежит в
`folio-data/review`.

## Обновления

Раз в день при запуске folio смотрит последний выпуск на GitHub. Более новая
версия скачивается в `folio-data/update/`, сверяется с опубликованным рядом
`.sha256` и распаковывается там; программу она заменяет, когда folio
закрывается — `.app` или AppImage переименовываются на место, в Windows файлы
папки копируются поверх, когда folio завершится (`folio-data/` не трогается), —
или сразу, по **Перезапустить и обновить** в настройках. В фоне ничего не
работает. **Проверить обновления** — проверить сейчас; **Проверять обновления
раз в день** выключает ежедневную проверку.

Контрольная сумма доказывает, что архив — тот, что назван в выпуске, и цел;
она приходит по TLS из того же выпуска, поэтому не доказывает, кто выпуск
сделал. Для этого есть подпись происхождения сборки:
`gh attestation verify folio-….zip --repo dskripchenko/folio`.

## Одно окно

Повторный запуск выводит работающий folio на передний план, а не запускает
вторую копию; документы открываются вкладками этого окна.
