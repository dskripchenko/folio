# Как устроено

## Два вида процессов

folio — приложение на Electron, и Electron делит его на две части:

- **Главный процесс** владеет окнами, меню, диском и правилами сети. Только он
  читает и пишет файлы.
- **Окно документа** рисует документ. Оно работает с изоляцией контекста и
  песочницей Chromium, без Node.js, под политикой безопасности содержимого,
  которая разрешает только скрипты самого folio. Что оно может попросить у
  главного процесса, проходит через маленький мост (скрипт preload) — открыть,
  сохранить, прочитать файл проекта — и больше ничего.

## Что может документ


Markdown-файл может прийти откуда угодно, поэтому окно ему не доверяет:

- он видит файлы папки, из которой открыт, — их отдаёт своя схема folio, — и
  ничего за пределами этой папки;
- в сеть — «Попробовать» в справочнике API, картинка или видео по адресу — он
  ходит только после того, как вы разрешили это для файла или папки;
- он не может увести окно на другую страницу или открыть новые окна; ссылка
  открывается в системном браузере.

## Окно

Середина отдана странице; элементы управления — по краям.

- **Слева — рабочее пространство.** «Общие» и проекты, у каждого дерево
  документов. Вверху: открыть файл, новая быстрая заметка, свернуть. У каждого
  раздела своё меню: «Общие» — их папка; «Проекты» — **+** добавляет папку или
  клонирует репозиторий, **⋯** показывает скрытые проекты. Ветка репозитория —
  метка рядом с именем. **Свёрнутая** (`Cmd/Ctrl+B`) панель — узкая лента:
  «Общие» и каждый проект своими инициалами; щелчок выдвигает его дерево поверх
  страницы, пока не открыт документ.
- **Сверху — вкладки**, и только они.
- **Тулбар редактора плавает над страницей** и остаётся под рукой, как бы
  далеко вниз ни ушёл текст; у самой страницы нет рамки. В режиме **Markdown** текст занимает всё
  рабочее пространство от края до края; **рядом со страницей** — две половины
  встык через линию, каждая прокручивается сама.
- **Справа — лента.** Одна кнопка показывает, как показан документ, и по
  щелчку переключает режимы по кругу — **Чтение**, **Править визуально**,
  **Markdown**, **Markdown рядом со страницей** (у схемы — чтение и правка, у
  draw.io — чтение); правый щелчок — список, чтобы выбрать сразу. Затем история, печать и PDF; внизу — настройки
  (тема: как в системе, светлая, тёмная).

## Как открыть документ

Markdown-файл открывается через **Файл → Открыть**, перетаскиванием на окно, из
командной строки (`folio notes.md`) или — если folio уже запущен — повторным
запуском с файлом: его откроет работающий folio. Ссылка на другой документ той
же папки открывает его во вкладке. Открытые документы и активный возвращаются
после перезапуска.

### Файлы схем и описаний API

Не только Markdown: схема или описание API открывается в своей вкладке и
рисуется своим элементом embed; ссылки на такие файлы в документе тоже их
открывают.

| Файл | Рисует | Правится в |
|---|---|---|
| `.bpmn`, `.dmn` | `<dsk-bpmn>`, `<dsk-dmn>` | их редакторах: палитра, контекстное меню, свойства, отмена |
| `.drawio`, `.dio`, `.drawio.svg` | `<dsk-drawio>`, вкладки страниц | — (только просмотр) |
| OpenAPI / Swagger (`.yaml`, `.yml`, `.json`) | `<dsk-openapi>`, справочник | его визуальном редакторе с исходником и превью |
| AsyncAPI (`.yaml`, `.yml`, `.json`) | `<dsk-asyncapi>` | исходник рядом с живым превью |
| `.mmd`, `.puml`, `.dot`, `.gv`, `.d2`, `.dbml`, `.dsl`, `.wardley` | `<dsk-diagram>`, синтаксис по расширению | исходник рядом с живым превью |
| код, данные, логи, конфигурация — любой текстовый файл известного языка (17 языков программирования, JSON, XML, логи, TOML, INI, `.env`, CSV, diff, Dockerfile, Makefile, …) | пронумерованные строки в цветах его языка (`@dskripchenko/syntax`; язык — по имени, расширению или строке `#!`); файл данных (JSON, YAML, XML, TOML, CSV, INI, `.env`) проверяется — ошибки отмечены у своих строк, счётчик в шапке переходит по ним; блоки сворачиваются стрелками у номеров; большой файл (больше 2 МБ или 20 000 строк, до 200 МБ) рисует только видимые строки, а свыше 5 МБ только читается; лог фильтруется по уровню (трассировка остаётся при своей записи) и, если читать его с конца, следует за дописываемым | исходник |
| другой текст | как текст | исходник |

YAML и JSON узнаются по ключу верхнего уровня `openapi`, `swagger` или
`asyncapi`; в дереве — YAML-файлы и JSON с именем как у описания API
(`openapi.json`), а не каждый `package.json`. API без сервера в сети
открывается без «Попробовать», а примеры запросов в нём — на
`http://localhost`. Сохранение, несохранённые правки, переживающие
перезапуск, история и сравнения работают для этих файлов так же, как для
Markdown.

## Общие и проекты

Рабочее пространство из двух частей: **Общие** — одна папка для документов,
общих для всего (по умолчанию `folio-data/library` или папка на ваш выбор), и
**проекты** — любые папки на диске, добавленные в folio. Список лежит в
`folio-data/workspace.json`; сами папки остаются, где были. Документ проекта или
«Общих» может читать файлы всей этой папки; отдельно открытый файл — своей папки.

Боковая панель показывает «Общие» и проекты: сначала закреплённые, потом по
группам, потом остальные; меню проекта (правая кнопка) закрепляет его,
переименовывает, кладёт в группу, скрывает или убирает из folio (папка на
диске остаётся). Деревья показывают папки и файлы, которые folio открывает,
папки первыми, и следят за диском: файл, добавленный, изменённый или удалённый
в другом месте, виден сразу, а открытый документ перерисовывается.
`Cmd/Ctrl+B` прячет панель.

## История в git

Для каждой папки отдельно — «Общих» и каждого проекта — и только по желанию.
Папка-репозиторий git (или папка внутри него) показывает историю сразу; другая
заводит её кнопкой **Вести историю** на панели **История** (`Cmd/Ctrl+Shift+H`):
репозиторий на ветке `main` и первый коммит того, что в папке есть.

- **Фиксировать при сохранении** — включено для истории, заведённой folio, и
  выключено для уже существующего репозитория (folio не коммитит в чужой
  проект сам). Сохранённый файл фиксируется через 3 минуты после последнего
  сохранения, так что серия сохранений даёт один коммит; при выходе из folio
  ожидающее фиксируется сразу. Фиксируется только сохранённый файл, с
  сообщением *Update <путь>*; **Зафиксировать** со своим сообщением делает это
  сразу.
- **Версии** открытого файла, новые сверху. Версия открывается только для
  чтения, как была; **Изменения** показывают разницу с текущей построчно,
  **Рядом** — два отрисованных документа, со схемами. **Вернуть эту версию**
  кладёт её текст в редактор как несохранённую правку — сохранять или нет,
  решаете вы.
- **В дереве**: изменённые файлы помечены, папка с изменениями внутри — точкой,
  у проекта видна ветка.
- Автор — `user.name` / `user.email` из конфигурации репозитория, затем из
  `~/.gitconfig`, иначе пользователь системы.

git встроен в folio (isomorphic-git, чистый JavaScript), поэтому всё это
работает там, где git не установлен.

### Ветки и синхронизация

- **Ветки**: имя ветки в панели открывает список — перейти на другую или
  создать новую от текущего места. Переход не выполняется, пока в файлах есть
  изменения, которые он перезаписал бы (ждущие паузы коммиты делаются сначала).
- **Удалённый репозиторий**: папке без него адрес задаётся в панели;
  репозиторий, клонированный в folio (**Файл → Клонировать репозиторий…** или ⤓
  рядом с «Проектами»), приходит со своим и становится проектом с включённым
  «Фиксировать при сохранении».
- **Синхронизировать** — получить, принять коммиты удалённого репозитория
  (перемотка вперёд или коммит слияния, если двигались обе стороны) и отправить
  свои; на кнопке видно, сколько уходит и приходит (↑ ↓). Все изменения должны
  быть зафиксированы.
- **Конфликт** остаётся в тексте, как его оставляет git: обе версии между
  строками `<<<<<<<` и `>>>>>>>`, файлы перечислены в панели. Поправьте их (в
  folio или где угодно), сохраните и нажмите **Завершить слияние** — пока
  остаётся маркер, слияние не завершится; **Отменить слияние** возвращает вашу
  версию. Слияние хранится так же, как у git (`MERGE_HEAD`), — системный git его
  тоже видит, — и до завершения сохранение не создаёт коммитов.
- **Сеть**: через системный git, если он установлен, — его помощники учётных
  данных и SSH-ключи работают как в терминале (пароль в невидимом терминале он
  не спрашивает). Без него folio сам говорит по HTTPS: когда удалённый
  репозиторий просит войти, панель принимает пользователя и токен; они хранятся
  зашифрованными средствами системы (Keychain, DPAPI, Secret Service) в
  `folio-data/logins.json` — или только до конца сеанса, если шифрования в
  системе нет. Синхронизация — ваше действие, согласия на сеть, как у
  документов, она не требует.

### Граф коммитов

Рядом со списком — граф как в Fork: по полосе на линию разработки, слияния —
кольца, соединяющие полосы, ветки идут рядом с основой и возвращаются в неё.
**Этот файл** — версии файла, линии проходят сквозь коммиты, которые файл не
трогали (как упрощает историю `git log -- file`); **Все коммиты** — весь
репозиторий: его ветки, ветки удалённого репозитория на момент последнего
получения и теги — с подписями на коммитах, текущий отмечен. Выбор коммита
открывает файл таким, каким он был тогда. Граф рисует `@dskripchenko/diagrams`
(`renderCommitGraph`).

## Несохранённое и быстрые заметки

Как в Sublime Text: безымянная вкладка — быстрая заметка, а несохранённая правка
не попадает в файл. И то и другое пишется в `folio-data/session/` по ходу
набора, поэтому переживает закрытие folio, сбой и перезагрузку компьютера и
возвращается в том же виде. Вкладка с несохранёнными правками помечена точкой.
Закрытие такой вкладки спрашивает, сохранить ли; закрытие folio не спрашивает
ничего — всё уже на диске. Если файл изменился на диске, пока вы правили,
folio говорит об этом и хранит оба варианта: взять файл с диска или оставить
свою версию и сохранить её поверх. Быструю заметку **Сохранить** кладёт в
«Общие» (или куда угодно), с именем по её первой строке.

## Печать

**Файл → Печать** (`Cmd/Ctrl+P`) печатает активный документ как документ:
в режиме чтения, а не правки; боковая панель, вкладки, кнопки и история folio
на бумагу не попадают, а бумага светлая, какой бы ни был экран. Каждый виджет
печатается в своей форме для печати из embed (`DskEmbed.print.prepare`):
схема BPMN или DMN целиком (файл DMN — с таблицами решений), все страницы
draw.io, процесс или доска целиком, справочник API — своим статическим
документом, видео — постером и главами, канбан и календарь — без элементов
управления. Дальше открывается системный диалог печати; PDF сохраняется через «Экспорт в PDF» (ниже).

### PDF

**Файл → Экспорт в PDF** (`Cmd/Ctrl+Shift+P`) сохраняет активный документ —
как он показан, с несохранёнными правками, — а **Экспорт папки в PDF** (меню
проекта или папки в дереве) сохраняет всю папку одним PDF. Диалог спрашивает
один раз и запоминает:

- размер страницы (A4, A3, A5, Letter, Legal, Tabloid), книжная или
  альбомная, поля (без полей, узкие, обычные, широкие);
- название вверху каждой страницы, номера страниц (`3 / 12`) внизу;
- оглавление со ссылками перед текстом; закладки по заголовкам (структура
  PDF, в размеченном PDF);
- цвета и фоны схем.

Папка печатается в порядке книги: в каждой папке сначала `index.md` или
`README.md`, затем документы по имени, затем вложенные папки; каждый документ
с новой страницы, файлы схем и API — с именем файла заголовком. Ссылка из
одного документа на другой становится ссылкой внутри PDF. Страницы
раскладываются в скрытом окне сеанса документов — согласие на сеть действует
и там — с каждым виджетом в форме для печати, затем Chromium печатает их в PDF.

## Правка

`Cmd/Ctrl+E` (или **Править** на панели) превращает документ в редактор и
обратно. У редактора три режима: визуальный (правка как в текстовом
процессоре — панель инструментов, меню `/`, все блоки живые), сам Markdown и
оба рядом. Файл остаётся Markdown: то, что визуальный режим не держит
(заголовки ниже h3, чек-листы, выноски, HTML), сохраняется как написано, а
картинки сохраняют свои относительные пути.

| Клавиши | |
|---|---|
| `Cmd/Ctrl+N` | быстрая заметка |
| `Cmd/Ctrl+O` | открыть файл |
| `Cmd/Ctrl+S`, `Cmd/Ctrl+Shift+S` | сохранить, сохранить как |
| `Cmd/Ctrl+E` | править / читать |
| `Cmd/Ctrl+W` | закрыть вкладку |
| `Cmd/Ctrl+B` | боковая панель |
| `Cmd/Ctrl+T` | перейти к файлу по имени |
| `Cmd/Ctrl+Shift+F` | поиск по файлам |
| `Cmd/Ctrl+F` | найти в документе |
| `Cmd/Ctrl+G`, `Cmd/Ctrl+Shift+G` | следующее совпадение, предыдущее |

## Поиск

`Cmd/Ctrl+Shift+F` (**Правка → Найти в файлах** или лупа на правой ленте)
открывает панель рядом со страницей: поиск по тексту файлов — всех, «Общих» или
одного проекта — с теми же тремя настройками. Совпадения появляются по мере
нахождения, по файлам, каждая строка — с совпадением; щелчок открывает файл, и
строка поиска встаёт на это совпадение. Двоичные файлы, файлы больше 8 МБ и
папки, исключённые из перехода к файлу, не просматриваются; показывается не
больше 200 совпадений на файл и 5 000 всего.

Стрелка перед запросом открывает **Замену**: у каждого совпадения видно, во
что оно превратится, флажки отмечают файлы, которые участвуют, а **Заменить
всё** переспрашивает с числом совпадений, прежде чем писать. С регулярным
выражением `$1`, `$&` и подобные означают его группы; без него текст берётся
как есть. Файл, открытый с несохранёнными правками, пропускается (об этом
сказано), чтобы не потерять ни одну из версий; открытый без правок — показывает
новый текст. Папка с историей получает один коммит на всю замену —
`Replace "a" with "b"`, — а не коммит на каждый файл.

`Cmd/Ctrl+T` (**Файл → Перейти к файлу**) открывает палитру всех файлов,
которые folio открывает, в «Общих» и видимых проектах; список ранжируется по
мере набора имени: символы по порядку, не обязательно подряд — `rn` находит
`release-notes.md`, первые буквы слов весят больше всего, совпадение в имени —
больше, чем в папках. Стрелки выбирают, Enter открывает, Escape закрывает.
Список собирается по папке один раз и держится, пока в ней не появится или не
исчезнет файл; папки зависимостей и сборки (`vendor`, `dist`, `build`,
`target`, `coverage`…) в него не входят, хотя дерево их показывает.

`Cmd/Ctrl+F` (**Правка → Найти**) открывает строку поиска над страницей: все
совпадения отмечены, текущее показано; Enter и Shift+Enter переходят по ним,
счётчик показывает, где вы. **Aa** — с учётом регистра, **ab** — слово целиком
(в любом алфавите), **.\*** — регулярное выражение. В чтении и визуальном
редакторе ищется страница как она нарисована — совпадение не переходит из
абзаца в абзац, а сама страница не меняется; в исходнике Markdown и в файлах,
которые правятся как текст, ищется поле, и по Escape текущее совпадение
остаётся выделенным в нём; большой файл ищется целиком, а не только по видимым
строкам. Если страница меняется под строкой поиска — правка, файл изменился на
диске, — поиск повторяется.

## Где лежат данные

Electron по умолчанию хранит данные в профиле пользователя. folio переносит их
все — настройки, кэши, данные сеанса, журналы — в `folio-data/` рядом с
программой:

| Как запущен | `folio-data/` |
|---|---|
| Windows | рядом с `folio.exe` |
| macOS | рядом с `folio.app` |
| Linux | рядом с файлом `.AppImage` |
| задан `FOLIO_DATA` | этот каталог |
| из исходников | `.folio-data/` в рабочем каталоге |

Поэтому удаление папки программы удаляет всё, что она когда-либо записала.
Обратная сторона: в папку должна быть возможна запись — не распаковывайте folio
туда, куда пишет только администратор.

## Одно окно

Повторный запуск выводит работающий folio на передний план, а не запускает
вторую копию; документы открываются вкладками этого окна.
